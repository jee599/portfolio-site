의료·치과 광고 리서치는 손이 많이 간다. 네이버 공식 공지를 읽고, SERP를 관찰하고, 가설을 업데이트하고, 롤링 지식베이스에 녹여야 한다. 매일 반복된다. 그래서 Claude Code로 데일리 리서치 에이전트를 만들었다.

**TL;DR** 세션 1개, 5분, 25 tool calls. 5/14 플레이스광고 노출 개수 상향과 5/13 신규 전환지표 추가를 포착하고 4개 파일을 자동 업데이트했다.

## 에이전트한테 던진 프롬프트

긴 시스템 프롬프트를 한 방에 넣었다. 역할 정의, 처리할 파일 목록, 근거 원자료 경로, 라벨링 규칙까지 한 블록으로.

```
너는 의료·치과 광고 데일리 리서치 에이전트다. 다음 파일들을 읽고
2026-05-09 데일리 업데이트 초안을 생성/갱신하라.
반드시 라벨링(공식 확인/공식 도움말 기반 해석/공개 SERP 관찰/
업계 관찰/합리적 유추/확인 필요/수치 미확인/고지출 추정)을 지키고,
특정 병원명은 최종 요약 중심에서는 패턴화하라.

업데이트할 파일:
- research/daily-medical-dental-ads/2026-05-09-daily-update.md
- rolling-knowledge-base.md
- source-index.md
- competitive-serp-observations.md
- naver-ranking-hypotheses.md

근거 원자료:
- research/daily-medical-dental-ads/raw-2026-05-09.json
- research/daily-medical-dental-ads/naver-notice-details-2026-05-09.json
```

이 구조의 핵심은 **출력 파일 목록을 명시**한 것이다. 에이전트가 "뭘 써야 하는지" 헷갈리지 않는다. 입력(원자료 JSON) → 처리(분석·라벨링) → 출력(파일 목록) 흐름이 프롬프트 안에서 완결된다.

## 5분 안에 포착한 신호 2개

`claude-opus-4-7`이 `raw-2026-05-09.json`과 `naver-notice-details-2026-05-09.json`을 읽고 추출한 핵심 변경사항이다.

**신호 1 — 5/14부터 플레이스광고 노출 개수 상향**  
병의원을 포함한 모든 업종에 적용되는 공식 공지다. 플레이스광고는 지역 기반 치과 마케팅에서 중요한 채널이라 즉시 `rolling-knowledge-base.md`에 반영했다.

**신호 2 — 5/13부터 검색광고에 '구매완료 광고수익률(%)' 전환지표 추가**  
파워컨텐츠·플레이스 캠페인은 제외다. 치과 검색광고 최적화에 직접 영향을 주는 새 지표가 생긴 셈이다.

공지 하나를 읽고 끝내는 게 아니다. `naver-ranking-hypotheses.md`에 이미 쌓인 가설과 연결해 "이 변경이 기존 관찰 데이터를 어떻게 재해석하게 만드는지"까지 업데이트했다.

## SERP 관찰 8건과 라벨링

`competitive-serp-observations.md`에는 이날 SERP 관찰 8건이 추가됐다. 에이전트는 라벨링 규칙을 따라 각 관찰에 출처 유형을 명시했다.

의료광고 분야에서 "알고리즘이 바뀐 것 같다"는 표현은 컴플라이언스 리스크다. 라벨이 없으면 6개월치 관찰 데이터가 쌓여도 팩트와 추론이 뒤섞여 쓸모없어진다.

- `[공식 확인]` — 광고 공지에 명시된 것만
- `[공개 SERP 관찰]` — 직접 검색해서 확인한 것
- `[합리적 유추]` — 공식 자료 기반으로 추론한 것
- `[확인 필요]` — 공식 근거가 없는 것

자연검색·플레이스 일반 랭킹은 네이버 비공개 정책상 `[공개 SERP 관찰]` 이상으로 올릴 수 없다. 이 규칙을 프롬프트에 명시해야 에이전트가 지킨다.

## tool call 분포

| 도구 | 횟수 | 주 용도 |
|------|------|---------|
| Edit | 8 | 기존 파일 부분 수정 |
| Bash | 7 | 파일 존재 확인, 디렉토리 탐색 |
| Read | 6 | 원자료 JSON + 기존 마크다운 읽기 |
| Write | 1 | `2026-05-09-daily-update.md` 신규 생성 |
| TodoWrite | 2 | 작업 체크리스트 관리 |
| ToolSearch | 1 | 사용 가능 도구 확인 |

Bash 7회가 눈에 띈다. 파일 경로가 여러 겹으로 중첩된 리서치 디렉토리 구조라서 에이전트가 경로를 자주 확인했다. 프롬프트에 절대 경로를 명시하면 Bash 호출을 줄일 수 있다.

## 이 구조가 작동하는 이유

데일리 리서치 에이전트가 안정적으로 돌아가는 건 입력이 구조화돼 있기 때문이다. 원자료를 JSON으로 떨어뜨리고, 에이전트는 그걸 읽어서 마크다운으로 가공한다.

"인터넷 검색해서 뉴스 찾아"라고 하면 매번 다른 결과가 나온다. "이 JSON 파일 읽고 이 파일에 써"는 재현 가능하다.

`rolling-knowledge-base.md`가 이 구조의 핵심이다. 매일 업데이트가 누적되면서 에이전트가 새 신호를 기존 컨텍스트 위에 올린다. 단발 분석이 아니라 시계열 추적이 가능해지는 이유다.
