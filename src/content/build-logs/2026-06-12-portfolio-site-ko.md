어제 하루 24개 세션이 열렸다. 총 tool call은 700회가 넘고, 가장 긴 세션 하나가 359회를 차지했다. 텔레그램 플러그인이 비활성화되어 모바일에서 Claude Code가 안 됐다는 것을 파악하는 것부터 시작해서, 31개 에이전트로 사주 글로벌 GTM을 조사하고, 커피챗 사이트를 완전히 새로 만들고, 치과 광고 KB를 22개 에이전트로 최신화하는 것까지 — 한 날 하루 안에 다 처리됐다.

**TL;DR** `settings.json`에서 `"telegram@claude-plugins-official": false` 한 줄 때문에 텔레그램 연결이 끊겼었다. `true`로 바꾸고 나서 모바일에서 Claude Code를 제어하는 게 다시 됐다. 그날 처리한 작업 중 가장 큰 건 사주 글로벌 GTM 리서치(31 에이전트, 814회 tool call, 43분)와 커피챗 사이트 완전 리빌드(177 Bash + 54 Chrome 조작)였다.

## 텔레그램이 왜 갑자기 안 됐나

"연결 안됐어 확인해줘"라는 메시지를 받고 `~/.claude/settings.json`을 열었다. 5월 말 하네스 정리 때 플러그인을 일괄 비활성화하면서 텔레그램도 같이 꺼진 것이었다. `false`를 `true`로 바꾸고 재시작하니 바로 텔레그램 메시지가 들어오기 시작했다.

텔레그램 연동의 실질적인 가치는 이거다 — 외출 중에도 "작업중이여?" 한 마디로 상태를 확인하고, "사주프로젝트 정리해줘"라고 하면 Claude Code가 바로 `STATUS.md`를 읽고 정리해서 답장을 보낸다. 이날 텔레그램으로 들어온 커맨드가 사주 프로젝트 상태 확인, Git 연동 활성화, 전 기능 동작 검증이었는데 모두 Claude Code 세션이 자동으로 처리했다.

## 커피챗을 30시간 세션 하나로 다시 만들다

세션 9가 이번 주에서 규모가 가장 컸다. 177회 Bash, 54회 Chrome 브라우저 조작, 43회 Edit, 30회 Write — 합계 359회 tool call이었다.

시작 프롬프트는 단순했다:

> "커피챗 사이트를 리뉴얼해서 멘토와 멘티를 이어주는 플랫폼이 아니라, 1. 내용채우면 이력서 만들어주고, 2.포트폴리오 점검해주고 3.에이전트3명을 둬서 에이전트는 글로 쓰고, 사람은 말로하게 해서 모의 면접을 하는 사이트를 만들고 싶어"

기존 코드베이스 분석, 3개 AI 기능(이력서 빌더·포트폴리오 분석·모의 면접) 설계, 구현까지 한 세션에서 끝냈다. 면접 로직은 공고/포트폴리오가 없어도 분야·경험·해본 일을 먼저 물어본 뒤 그 답변을 기반으로 꼬리무는 질문을 생성한다. 모델도 기능별로 달리 했다 — 면접은 Opus(품질 우선), 이력서는 Sonnet(비용), 포트폴리오 분석은 Opus.

디자인 피드백은 중간에 여러 번 들어왔다. "너무 AI 사이트 같다", "색감이 이상하다", "파비콘 배경이 투명하지 않다". 이런 피드백이 오면 Chrome으로 렌더를 바로 확인하면서 고쳤다. GPT Image 2.0 API로 Toss 톤의 3D 에셋을 생성해서 붙이고, 파비콘도 재생성했다. 브라우저 실측이 같은 세션 안에서 루프를 돌 수 있어서 디자인 이터레이션이 빨리 됐다.

## 31개 에이전트로 사주 글로벌 GTM 조사

세션 10에서 `fortunelab.store` 글로벌 GTM 전략을 조사했다. Workflow tool로 31개 에이전트를 병렬로 띄워 43분 만에 814회 tool call을 처리했다.

조사 결과 중 포지셔닝을 바꾼 발견이 있었다. Etsy 실측 데이터 — AI 명시 상품은 판매 0, 인간 페르소나 상품은 1년에 464판매. 이 숫자 하나가 랜딩 방향을 결정했다. AI를 앞에 내세우지 않고 "1,000년 한국 전통 사주 + 정밀 만세력 계산"으로 포지셔닝하는 것이다. Saju.com 영문판도 '청월 선생'이라는 페르소나를 쓰고 있었다.

리서치 출력물은 HTML 보고서(`FORTUNELAB_GTM_DEEPRESEARCH_2026-06-11.html`)로 만들었다. 로드베어링 주장 52건을 전부 적대 검증 — 확인 38, 교정 13, 미검증 1. 보고서에 숫자를 쓸 때 브라우저로 실측해서 가져왔고, 검증에서 걸린 건 교정값으로 바꿨다.

## 치과 광고 KB 최신화: 22 에이전트, 12차원, 적대검증 30건

세션 11에서는 치과 온라인 광고 전 채널 리서치를 했다. 12차원 병렬 리서치(네이버 검색광고·스마트플레이스·블로그 알고리즘·AEO/GEO·구글·메타·유튜브·카카오/당근·의료법·리뷰·예약플랫폼·트렌드 비용)에 고위험 6차원은 핵심 주장 5개씩 적대 검증이 추가됐다.

적대 검증이 실제로 틀린 주장 4건을 잡았다. "헌재 비급여 할인 결정은 2025년"이라는 게 실제로는 2019-05-30이었고, "영수증 리뷰 POS 연동 필수"는 선택적 대체 인증이 가능한 것이었다. 에이전트를 믿고 검증 없이 썼으면 틀린 정보가 KB에 들어갈 뻔했다.

작업 중에 API 과부하(529 오류)로 dental-clinic 에이전트가 65회 tool call 후 죽는 일도 있었다. 파일 상태를 확인해 어디까지 됐는지 파악하고 남은 작업을 이어서 처리했다. 에이전트가 죽어도 파일이 남아 있어서 재시작 없이 이어 붙이는 게 됐다.

## 도구 사용 패턴

24세션 합산 주요 tool call:

- Bash: 390회 이상 (서버 실행, git, API 테스트)
- Edit: 110회 이상 (파일 수정)
- mcp__claude-in-chrome__browser_batch: 71회 (렌더 확인, 지도 실측)
- Write: 35회 (신규 파일 생성)
- Workflow: 6회 (대규모 fan-out 리서치)

세션별로 보면 세션 9(커피챗 리빌드, 359회)와 세션 8(사주 Telegram 제어, 197회)이 압도적으로 많고, 세션 3-7은 claude-haiku-4-5가 사주 궁합 텍스트를 자동 생성하는 배치라 tool call 0이었다.

멀티에이전트 패턴에서 실제로 확인한 것 — `pipeline()`이 `parallel()` 배리어보다 wall-clock 기준으로 빠르다. 에이전트 A가 3단계에 있을 때 에이전트 B가 1단계를 돌고 있는 구조가, 전부 끝날 때까지 기다리는 배리어보다 느릴 이유가 없다. 31-에이전트 리서치가 43분에 끝난 것도 이 덕분이다.
