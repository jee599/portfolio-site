532번. 커피챗 프로젝트 단일 세션의 tool call 수다. 27시간 48분 동안 `Bash` 190번, `Edit` 136번, `Write` 66번을 찍었다. 인증(이메일/비밀번호 + JWT), PayPal 결제(create-order → capture → webhook), OpenAI TTS, next-intl 7개 로케일, 어드민 대시보드, 디자인 QA까지 한 세션에서 끝냈다.

**TL;DR** 6월 11~12일 Fable 5로 7세션을 돌렸다. 총 1,199 tool call, 61개 파일 수정·115개 파일 생성. 사주 전면 리디자인, 커피챗 풀스택, 치과광고 보고서 + PPT, 창업 프로그램 전수 조사, spoonai P0 버그 수선까지 동시에.

## 커피챗 세션이 532 tool call까지 간 이유

처음 요청은 간단했다.

> "admin에서 각 유저별로 이메일/비밀번호로 로그인하게 해줘. 토큰 얼마나 쓰는지 볼 수 있게 해줘. 필요한 모든 운영툴 붙여줘."

"모든 운영툴"이라는 한 마디가 끝이 없었다. Turso DB 레이어(SQLite-over-HTTP) → 이메일/비밀번호 인증 + JWT 세션 쿠키 → 크레딧 계산 모듈 → PayPal 결제 세 개 엔드포인트(`/api/pay/paypal/create-order`, `/capture`, `/webhook`) → 어드민 사용자 목록·상세·액션 페이지 → i18n 라우팅(next-intl) → OpenAI TTS(`/api/tts`) → 포폴 심층보강 UI → 이력서 임포트·템플릿·export.

중간에 기능마다 독립 에이전트로 병렬 실행했다. `포폴 심층보강 인터랙티브 UI` 에이전트, `이력서 임포트·템플릿·export UI` 에이전트, `디자인 QA` 에이전트가 동시에 돌면서 task notification으로 완료를 보고했다. 메인 컨텍스트는 오케스트레이션만 하고 구현은 서브에이전트가 병렬로 처리하는 구조다.

배포 직전에 Vercel이 커밋을 차단했다.

```
The deployment was blocked because the commit author email 
(jidong@jidongui-iMac.local) is not valid.
```

`git config`의 `user.email`이 iMac 로컬 호스트명으로 설정돼 있었다. 25시간 작업 끝에 나온 블로커라 황당했지만, 이메일 수정 후 재커밋으로 해결.

## 사주 사이트: "전통 사주" 포지셔닝이 결제를 붙게 한다

사주 프로젝트에서 나온 가장 중요한 전략 결정이었다. 사용자 질문: "전통 사주로 하면 결제 플랫폼이 반려하지 않아?"

6/11에 이미 Etsy 자연실험 데이터가 있었다. 'AI Reading' 전면 샵 → 1개월간 판매 0건. 인간 페르소나 샵(연화 만신) → 1년 464건·리뷰 130개. 결제 플랫폼 심사역은 랜딩 카피가 아니라 **서비스 카테고리** 자체를 본다. 'AI 리포트'든 '전통 사주'든 생년월일 입력하고 운세 리포트 파는 서비스라는 사실은 심사 결과에 동일하게 적용된다.

전략 결론: 포장을 바꾸는 게 아니라 점술을 허용하는 결제 레일(Paddle·Lemon Squeezy 대안)로 이동하는 것이 맞다. 이전 세션 딥리서치 결과를 다음 세션에서 그대로 끌어와 판단 근거로 삼은 케이스다.

리디자인은 open-design 스킬로 진행했다. "Midnight Almanac" 컨셉 — 딥 잉크 인디고 + 골드 헤어라인 + Fraunces 세리프. 코스믹 3D 배경은 현 라이브 사이트의 `CosmicBackground`(three.js)를 그대로 이식하되 별을 골드 틴트로, 드리프트 속도를 낮췄다. gpt-image-2로 실사 이미지를 생성하고 SVG 도형 차트는 제거했다. v1(무애니메이션)·v2(3D + 패럴랙스)·v3(gpt-image-2 실사) 세 버전을 이터레이션했다. 총 356 tool call, 25시간 26분 세션.

## 에이전트 5개로 창업 프로그램 57개 전수 조사

프라이머 시드 액셀러레이터(마감 6/28, 1억 투자·지분 약 10%) 지원 검토 요청이 왔을 때, 직접 검색하는 대신 dynamic workflow를 썼다. 5개 카테고리로 검색 에이전트를 병렬 fan-out했다.

정부지원(DIPS Link-up 등)·민간 액셀러레이터·대기업 오픈이노베이션·AI특화/글로벌·상시 프로그램. 209회 검색·검증, 57개 프로그램 실측. 1인 창업자·AI 자동화 B2B·실 트랙션 보유 조건으로 거르면 즉시 사용 가능한 카드 7개, 공고 임박 모니터링 2개.

이 방식의 핵심은 에이전트마다 2026년 6월 현재 모집 상태를 공식 출처에서 독립 검증한다는 것이다. 크로스 레퍼런스로 신뢰도를 올렸다. 워크플로 완료 후 결론: 프라이머 지원 비용은 사실상 "1분 영상 하나"이고 충분히 지원할 가치가 있다.

## spoonai P0 수선: 22분에 배포까지

7번째 세션은 22분이었다. 도구 밀도는 가장 높았다 — `Bash` 25번, `Read` 13번, `Write` 8번, `Edit` 7번, 분당 약 2.5회.

버그: 신규 구독자가 메일을 영구히 못 받는 것 + 수신거부(unsubscribe) 404. `scripts/send-email.js`의 구독자 목록 로직이 신규 등록자를 포함하지 않았다. `/api/unsubscribe` GET 엔드포인트가 즉시 삭제하는 대신 확인 페이지로 302 리다이렉트하도록 수정하고, `/unsubscribe`·`/feedback` 페이지를 새로 만들었다. 커밋 `4a3c598` 배포, 라이브 검증 완료 — 22분 세션 안에 전부 끝냈다.

## 메모리 파일로 세션 간 컨텍스트 연속성 유지

이번 7세션 전부 Fable 5 모델이었다. 가장 눈에 띈 것은 `~/.claude/projects/.../memory/` 파일을 활용하는 방식이었다. 6/11 딥리서치에서 나온 Etsy 실측 데이터를 6/12 사주 전략 결정 세션에서 그대로 끌어다 쓴다. 별도로 context를 전달하지 않아도 메모리 파일에서 읽어오기 때문에, 세션이 끊겨도 작업 흐름이 이어진다.

문제는 메모리 파일이 오래될수록 오래된 판단을 근거로 쓸 수 있다는 점이다. 이번에도 `project_saju_paypal.md`가 한 번 업데이트됐다 — 실측으로 뒤집힌 가정을 정리했다.
