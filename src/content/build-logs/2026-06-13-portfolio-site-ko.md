이틀 동안 세션을 13번 열었다. 도구 호출은 1,492회, 세션 하나가 600회에 육박한다. daymoon 사진 사이트 리뉴얼, 사주 글로벌 서비스 UI 전면 교체, 커피챗 플랫폼 어드민·결제 시스템, 치과 원장님 브리핑 PPT까지 — 모두 같은 이틀 안이다.

**TL;DR** — 한 명이 이틀 안에 여러 프로젝트를 동시 진행한 건 멀티에이전트 오케스트레이션과 Open Design 강제 게이트 덕분이다. 세션 한도에 네 번 막혔고 동시 편집 충돌도 났다. 그 과정이 아래에 있다.

## 세션 규모가 이 정도면 구조가 필요하다

세션 10이 356회, 세션 11이 532회다. 단순히 "많이 썼다"가 아니라 한 세션 안에서 서브에이전트를 20개 이상 돌린다는 뜻이다. `/effort ultracode` 로 켜면 Claude가 자체 판단으로 동적 워크플로를 띄운다.

```
/effort ultracode
# → xhigh + dynamic workflow orchestration 활성화
```

사주 사이트 세션에서는 이런 식으로 에이전트를 동시에 흘렸다.

- **랜딩 페이지 리디자인** 에이전트 → 전면 리빌드
- **로딩 화면 캐스팅 시퀀스** 에이전트 → 별도 컴포넌트
- **페이월 페이지** 에이전트 → 결제 플로우
- **리포트 페이지** 에이전트 → 문서 모드 UI
- **7로케일 번역** 에이전트 → i18n 전체

이 다섯 개가 동시에 돌고, 완료 알림이 차례로 쌓인다. 각 에이전트가 끝나면 task-notification이 오고, 메인 세션은 통합만 한다. 총 소요: 약 9시간. 한 명이 직접 짰으면 며칠 걸렸을 작업이다.

## daymoon 사진 사이트: 293장과 어드민

daymoon은 사진작가 포트폴리오 사이트다. 요청은 단순했다.

> "다른 한국 포토그래퍼 작가들처럼 트렌디하고 작업물이 잘 보이게 사이트 리뉴얼해주고, 관리자 사이트도 만들어줘"

파일 읽기 결과: 실제 사진이 293장 있었다. 이걸 기반으로 Open Design 스킬이 방향 5개를 제시하고 "화이트 큐레이션"을 선택했다. 이후 진행:

1. 풀와이드 히어로 슬라이드쇼(대표작 12장 크로스페이드)
2. 동적 갤러리 그리드 — 카테고리별 필터
3. 어드민 3탭 시스템 — 사진 업로드/예약 인박스/시즌 설정
4. Vercel Blob 스토리지 연동 — 서버 경유 없이 50MB 원본 직업로드

세션 6은 216회 도구 호출, 10시간짜리였다. 중간에 "동시 세션이 OK 파일을 덮었습니다"라는 충돌이 났다. 같은 레포를 두 세션이 동시에 건드리면 이런다. 재설정 후 재시도했다.

세션 9에서는 운영 질문만 2개 들어왔다.

> "어드민에서 사진 올리면 어디에 저장돼?"

Bash 3회, Read 3회. 6회 도구 호출로 끝났다. 이미 만들어놨으니 설명만 하면 된다.

## 사주 글로벌: GPT-image-2 + 3D 코스믹 배경

사주 서비스에서는 결제 플랫폼 반려 문제부터 시작했다. 질문이 흥미로웠다.

> "전통사주로 하면 결제가 안 붙지않아?"

결론은 반대였다. 점술 카테고리 자체가 심사 이슈고, 포장을 바꿔도 카테고리는 바뀌지 않는다. 6/11 딥리서치에서 Etsy 자연실험 데이터로 확인했다 — 'AI Reading' 전면 샵은 1개월 판매 0건, 인간 페르소나 샵은 1년 464건.

디자인 방향은 "Midnight Almanac" — 딥 잉크 인디고 + 골드 헤어라인 + Fraunces 세리프. 코스믹 배경(three.js 별 드리프트)은 기존 라이브 사이트 감각을 이식했다.

이미지가 필요한 구간에서 GPT-image-2를 연동했다. 백그라운드 태스크로 생성하고 그동안 v3 코드를 짰다.

```python
# genimg.py — gpt-image-2 생성 스크립트
# 백그라운드로 돌리고 메인 세션은 UI 코드 진행
```

"회전하는 사주차트가 너무 유치하다"는 피드백이 왔다. SVG 도형 애니메이션 제거, 실사풍 이미지로 교체했다. 수묵화 이미지도 시도했는데 배경과 맞지 않아 다시 교체했다.

이 세션에서 "You've hit your session limit"가 두 번 났다. 세션 한도는 갑자기 온다. 이어서 재시작하면 컨텍스트가 끊기므로, 중요한 상태는 메모리 파일(`project_saju_paypal.md`)에 미리 써두는 습관이 필요하다.

## 치과 브리핑: 20장 → 13장 단순화

원장님 설명용 PPT를 만들었다. 첫 버전이 20장이었고 피드백이 왔다.

> "슬라이드만 봐서는 내용이 어려운 것 같은데 조금 더 이해하기 쉬운 톤으로, 내용도 줄이고"

20장 → 13장, 파트 구분 슬라이드 제거, AEO/CPC 같은 전문용어를 "클릭 1번 약 3만 7천 원"으로 풀어쓰기. 슬라이드당 숫자 개수 절반 이하로 제한했다. 기존 상세판은 보존.

세션 1(175회)과 세션 7(82회)이 치과 작업이었다. 치과 서브에이전트(`dental-clinic`)에 위임하는 구조인데, 이 두 세션은 메인 세션이 직접 잡았다.

## Open Design 강제 게이트

모든 HTML 산출물은 Open Design 스킬을 거쳐야 한다. 이건 CLAUDE.md에 박힌 하드 게이트다.

```
# CLAUDE.md 발췌
# Hard gate for any visual deliverable:
# 어떤 HTML/PDF/웹 산출물도 Open Design 또는 OD-equivalent 
# 디자인시스템 패스 없이 deliverable로 취급하지 않는다.
```

`hooks/design-gate.sh`가 `.html/.htm` 파일 작성을 블록하고, `hooks/design-pass.sh`로 세션을 OD 패스로 명시해야 열린다. 이게 없으면 치과 보고서 HTML을 쓸 때마다 막힌다.

세션 7에서는 medical-report 네이비 테마를 이메일 호환판으로 변환했다. 세션 8에서는 `~/reports/시장분석_사장님보고.html`을 원형 삼아 owner-briefing 스킬로 갔다.

## ultracode 세션에서 배운 것

세 가지다.

첫째, 병렬 에이전트는 context가 공유되지 않는다. 각 에이전트가 독립적으로 파일을 읽어야 하므로, 공유 상태가 필요하면 파일로 쓰고 경로를 프롬프트에 넘겨야 한다.

둘째, 세션 한도는 도구 호출 수보다 시간에 연동된다. 10시간짜리 세션이 멀쩡히 돌다가 갑자기 막혔다. 장기 작업은 체크포인트 커밋을 중간에 하는 게 낫다.

셋째, "계속해"는 생각보다 강력한 프롬프트다. 세션 11에서 "계속해서 해"를 세 번 연속 쓰면서 커피챗 플랫폼의 어드민 인증, 토큰 추적, PayPal 결제, 다국어 지원까지 끊김 없이 진행했다. Claude가 메모리와 태스크 목록으로 상태를 유지하기 때문에 짧은 재촉도 충분히 작동한다.
