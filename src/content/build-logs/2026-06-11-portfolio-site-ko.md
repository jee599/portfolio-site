하루 12개 세션, 783번의 도구 호출. 그 중 가장 오래 걸린 세션은 29시간 26분짜리 커피챗 리뉴얼이었고, 가장 빠르게 풀린 건 텔레그램 연결 실패였다. 원인은 `settings.json`의 `false` 한 줄이었다.

**TL;DR** 텔레그램 플러그인이 꺼져 있어서 연결이 안됐다. 켜고 나서 폰에서 지시하면 Claude가 작업하고 텔레그램으로 결과를 보내는 루프가 완성됐다. 같은 날 워크플로우로 GTM 딥리서치(에이전트 31개)를 돌리고, 커피챗을 멘토-멘티 매칭에서 AI 이력서·포트폴리오·모의면접 플랫폼으로 교체했다.

## 텔레그램 연결 실패 — 원인은 settings.json 한 줄

세션 1에서 텔레그램 연결 방법을 물었다. 상태 확인 결과: 플러그인 v0.0.6 설치됨, Bun 1.3.11 설치됨, 유저 ID 허용 목록에 있음, 봇 토큰 파일도 있음. 준비는 다 됐는데 연결이 안됐다.

세션 2에서 다시 들어와서 원인을 찾았다. `~/.claude/settings.json`에 `"telegram@claude-plugins-official": false`로 박혀 있었다. 5월 말 하네스 정리 때 플러그인을 일괄 비활성화하면서 같이 꺼진 것이었다. `true`로 바꾸고 재시작하니 즉시 연결됐다.

이후부터 실제 운용 구조가 완성됐다. 세션 8에서는 텔레그램으로 "연결됐어?" 확인이 왔고, 이후 "사주 프로젝트 정리해줘", "깃연동 켜줘"가 순서대로 들어왔다. Claude가 메모리에서 컨텍스트를 복원하고, 작업하고, 결과를 텔레그램으로 회신하는 루프다. 자리를 비우거나 다른 작업을 하면서 Claude를 병렬로 제어할 때 실용성이 높다.

## 워크플로우로 대규모 리서치 — 에이전트 31개, 적대검증 52건

세션 10에서 사주 프로젝트 글로벌 GTM 딥리서치를 돌렸다. `ultracode` 모드로 Workflow를 쏘고 기다렸다.

결과: 에이전트 31개, 814회 tool call, 약 43분 소요. 13개 주제를 병렬로 리서치한 뒤 완전성 비평 에이전트가 갭 3건을 더 발견해서 보강 리서치를 추가로 돌렸다. 핵심 클레임 52건은 적대검증을 통과시켰다 — 확인 38건, 교정 13건, 미검증 1건.

```
리서치 에이전트 31개 → 완전성 비평 → 보강 리서치 3건
→ 핵심 주장 52건 적대검증 → 확인 38 / 교정 13 / 미검증 1
```

세션 11에서는 치과 마케팅 채널 리서치를 같은 패턴으로 돌렸다. 22 에이전트, 12차원 병렬 리서치(네이버 검색광고·스마트플레이스·블로그 알고리즘·AEO/GEO·구글·메타·유튜브·카카오·의료법 등), 적대검증 30건에서 틀린 주장 4건을 잡아 정정했다. "헌재 비급여 할인 결정은 2025년"이라고 쓰인 주장이 실제로는 2019-05-30이었다. 대행사 출처 문서에 날짜가 틀린 케이스가 꽤 나왔다.

도중에 dental-clinic 에이전트가 API 529 과부하로 65회 호출 후 강제 종료됐다. 파일 상태를 직접 확인했더니 대부분 완료된 상태였고, 남은 부분만 재실행해서 마무리했다.

워크플로우가 가장 유효한 경우는 이런 패턴이다: 독립적으로 처리 가능한 항목이 10개 이상이고, 결과 신뢰도를 적대검증으로 높여야 할 때. 단일 컨텍스트로는 절반도 커버 못한다.

## 피아노 연습실 보고서 — 8개 권역, 40건 매물, 카카오맵 실측

세션 9는 개인 용도 작업이었다. 구반포역 기준 15~20분 이내 그랜드 피아노 놓을 상가·오피스텔을 찾아달라는 요청.

Workflow로 8개 권역 에이전트를 병렬로 띄워 매물 40건을 수집했다. 그 다음 래미안 트리니원 기준 피아노 교습소 전제로 재평가 요청이 들어왔다. 여기서 중요한 발견이 나왔다 — 오피스텔은 건축물 용도가 업무시설이라 교습소 신고 자체가 안 될 가능성이 있었다. 용도 문제가 확인되자 적합도 스코어링이 완전히 뒤집어졌다.

이동시간은 `mcp__claude-in-chrome` 브라우저 실측으로 측정했다. 신논현역 8분(직통), 신사역 11분, 논현역 15분, 신대방삼거리역 30분(20분 조건 초과 → 탈락). 보고서에는 추정값이 아니라 실측값만 들어갔다.

## 커피챗 → AI 면접 플랫폼 — 29h 26min, 359 tool calls

세션 12가 하루 중 가장 긴 작업이었다. 기존 멘토-멘티 커피챗 사이트를 이력서 빌더 + 포트폴리오 분석 + 모의 면접 플랫폼으로 교체하는 것.

시작 프롬프트:

> "커피챗 사이트를 리뉴얼해서 1. 내용채우면 이력서 만들어주고, 2. 포트폴리오 점검해주고 3. 에이전트 3명을 둬서 에이전트는 글로 쓰고, 사람은 말로 하게 해서 모의 면접을 하는 사이트를 만들고 싶어"

기능 설계는 Claude한테 물어보는 게 아니라 직접 결정 항목을 정리해서 던졌다. "TTS 면접관 음성 불필요", "이력서 Sonnet / 포트폴리오·면접 Opus"처럼. 비용 계산도 직접 했다 — "Opus로 10~20분 면접이 얼마야?" → $0.45~$1.20 범위 확인 후 모델 확정.

디자인은 "AI로 만든 티가 나지 않아야 한다"가 핵심 요구사항이었다. 처음 만든 갈색·주황 조합이 "별로 안예뻐"로 기각됐고, GPT Image 2.0으로 생성한 아이콘도 배경 투명도 문제로 파비콘이 깨졌다. 피드백 루프를 몇 차례 돌린 끝에 Toss 톤 — 다크 히어로 `#171310` + 카라멜 글로우 + 벤토 그리드 + Linear 스타일 모션으로 고정됐다.

면접 로직에서 가장 신경 쓴 부분은 도메인 특화 질문이었다.

> "언리얼5 컨텐츠 프로그래머는 그래픽 질문을 받을 필요가 없고, 전투 프로그래머는 UI 딥한 질문을 받을 필요가 없다"

직군 + 연차(주니어/시니어 대신 실제 연차 숫자) + 포폴 or 공고 or 없을 때 도메인 질문으로 대체하는 setup 흐름을 `app/api/interview/setup/route.ts`에 구현했다. 포트폴리오·공고 없이 들어오면 분야·경험·해본 일을 먼저 수집하는 대화가 시작된다.

면접 진행 방식도 시스템 프롬프트로 명시했다: 경험 기반 꼬리 무는 질문, 답변에 파고드는 질문, "모르겠다"가 나오면 다른 각도로 전환. 코드 리뷰 에이전트가 이력서 위저드 5종·포트폴리오 3종·면접 4종·lib 4종 전체를 읽고 로직을 검토했다. stop hook이 `TODO` 잔재를 두 번 잡아냈고, 두 번 다 정리했다.

최종 도구 분포: Bash 177회, 브라우저 실측 54회, Edit 43회, Write 30회.
