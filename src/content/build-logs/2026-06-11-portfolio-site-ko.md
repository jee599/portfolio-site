하루에 11세션을 돌렸다. tool call 789번, 파일 68개가 만들어지거나 수정됐다. 소요 시간 합산 9시간이 넘는다.

**TL;DR** 가장 큰 덩어리는 CoffeeChat 리뉴얼 — 멘토-멘티 매칭 사이트를 AI 모의면접 플랫폼으로 갈아엎는 데 3시간 19분, 279 tool calls가 들었다. 동시에 JDLab 이메일 파이프라인을 4개 세션에 걸쳐 강화하고, Dynamic Workflow를 `CLAUDE.md`에 상시 승인으로 심었다.

## 3시간 19분, 279 calls — CoffeeChat을 AI 면접 플랫폼으로

요청은 세 줄이었다. "이력서 만들어주고, 포트폴리오 점검해주고, AI 면접관 3명이랑 모의 면접하는 사이트로 리뉴얼해줘."

기획서 없이 기능 3개가 동시에 들어온 케이스다. Claude가 먼저 결정이 필요한 부분을 분리했다 — 음성 TTS 지원 여부, 이력서 템플릿 종류, 면접관 역할 분담 방식. 음성은 불필요하다고 했고, 나머지는 합리적인 디폴트로 바로 빌드를 시작했다.

완성된 기능은 세 개다. **이력서 빌더**: 5단계 위저드(기본→경력→프로젝트→스킬·학력→미리보기), 항목별 "AI 다듬기" 기능, 모던 1p·한국 전통형 템플릿 2종. **포트폴리오 체크**: GitHub URL 제출 후 AI 점검. **모의 면접**: 포폴 + 공고 입력, AI 면접관 3명이 역할을 나눠 포폴 기준·기본지식·전문지식 축으로 진행.

디자인 피드백은 4라운드였다. "AI 사이트 같아" → "주황 갈색 별로 안예뻐" → "정적이야, 반응형 넣어줘" → "색감이 안 맞아". 매 라운드마다 `mcp__claude-in-chrome__browser_batch`로 실제 렌더를 확인하면서 수정했다. 브라우저 도구 33번 사용 중 전부 렌더 확인이었다. 결국 다크 히어로 + 카라멜 글로우 + 벤토 그리드 + 스크롤 모션으로 정착했다.

이 세션의 도구 분포: Bash 132, Edit 40, Write 28, Read 25, browser_batch 33. Bash의 대부분은 빌드 확인과 타입체크였다.

## Dynamic Workflow를 CLAUDE.md에 상시 승인으로 박기

기존 방식의 문제는 단순했다. 매번 "이 작업 dynamic workflow 써도 돼?"를 물어봐야 했다. 중간에 흐름이 끊기고, 내가 잊으면 그냥 단일 에이전트로 진행하거나 아예 안 썼다.

세션 10에서 `~/.claude/CLAUDE.md`에 사이즈 판단 기준을 박았다.

```
①  단순 조회/단일파일 → 직접 처리
②  멀티파일이지만 한 컨텍스트 → 서브에이전트 필요한 만큼
③  광범위 fan-out ("전수/꼼꼼히/comprehensive") → Workflow 재량 사용
```

설정하자마자 동백유디 치과 보고서 퀄업 요청이 왔다. ③에 해당하는 작업이었다. 내가 "워크플로우 써"라고 말하지 않았는데 알아서 5단계 workflow를 띄웠다 — context 복원 → 병렬 실측(플레이스 지표·경쟁사 probe·키워드 3개 병렬) → 보고서 생성 → 검증 → 기록·푸시. 에이전트 11개, 85분.

이전에는 이 흐름을 시작하기 전에 승인 대화가 한 번 있었다. 이제는 없다.

## JDLab 이메일 파이프라인 — 4세션 연속 하드닝

세션 4부터 8까지, 세션 6을 제외하면 짧게 치고 빠지는 방식으로 파이프라인을 강화했다.

**세션 4** — 이미 해결된 인바운드 답변 2건이 여전히 "핫 리드"로 잡혀있었다. `state/jdlab_resolved_replies.json`으로 분리하고, 해당 주소가 기본 설정에 나타나지 않음을 테스트로 검증했다.

**세션 5** — 바운스 CSV 파일이 절대경로로 하드코딩돼 있었다. 새 감사 실행마다 타임스탬프가 바뀌는데 크론이 항상 옛날 파일을 읽는 문제였다. `resolveBounceCsvSelection()`을 작성해서 헤르메스 캐시 디렉토리에서 가장 최신 파일을 자동 선택하게 바꿨다. 기존 28개 + 새 테스트 3개, 총 31개 통과.

**세션 6** — MX preflight 추가(free-mail 도메인 차단), `run_id` 크로스체크로 중복 발송 방지, draft 루프 예외 처리 강화. 이 세션 혼자 Edit 43, Bash 32였다. 작업이 많아서 `TaskCreate`로 단계를 추적하면서 진행했다.

**세션 8** — 컨택 티어링(cold·warm·hot 분류, 발송 윈도우 티어별 다르게), 템플릿 반복 방지 모듈 신설. 새 테스트 파일 5개 생성: `jdlab_contact_tier.test.js`, `jdlab_send_window_caps.test.js`, `jdlab_template_repetition.test.js`, `jdlab_codex_wrapper_policy.test.js`, `jdlab_copy_calibration.test.js`.

처음 목표는 "반응이 없어서 품질을 올린다"였다. 매 세션마다 테스트 먼저 작성하고 코드를 바꾸는 방식으로 진행했다. 총 테스트 파일 5개 새로 생겼고 기존 테스트도 확장됐다.

## 지원서를 Claude Code로 작성하기

세션 7에서 Spark Claw 스타트업 지원서를 작성했다. 폼 항목이 10개가 넘고, 내 프로젝트와 경험에 맞게 채워야 했다.

첫 답변은 AI 냄새가 났다. "첫째로~", "핵심 차별점은 다음과 같습니다" 같은 패턴. 지시는 단순하게 줬다: "AI 티나는 수식어 빼고, 내 경험을 많이 녹여줘." 이터레이션 3번 만에 실측 데이터(파일럿 치과 진단 수, 시장조사 업체 수)를 근거로 쓴 건조한 답변이 나왔다.

동시에 회사 소개서 1장짜리 PDF도 만들었다. open-design 루트를 타서 A4 HTML을 만들고 PDF로 변환했다. `#533afd` jidonglab 브랜드 컬러, 라이브 프로덕트 4종 표 포함, 502KB.
