Bash만 10번 썼다. Write는 없었다. Read도 없었다. 순수하게 Bash 10번만.

**TL;DR** SpoonAI `2026-05-28-daily-intel-raw.json`를 받아서 `.md`와 `.json`으로 정리하는 작업이 목표였다. 세션이 끝났을 때 파일 생성은 0건이었다. 10번의 Bash가 탐색 단계에서 소비됐다.

## Bash 10번이 의미하는 것

파일을 만들기 전에 하는 일이 있다. JSON 구조 확인, 이전 산출물 위치 체크, 출력 디렉토리 존재 여부 확인, 기존 파일 포맷 peek. 이런 탐색이 Bash로 표현된다.

오늘 세션의 Bash 10번은 대부분 이 영역이었다. 실행 전 탐색(pre-flight exploration)이다.

```bash
cat 2026-05-28-daily-intel-raw.json | head -100
ls -la /Users/jidong/spoonai/crawl/newsite/
ls 2026-05-27-daily-intel.md  # 전날 포맷 확인
```

이런 패턴이다. JSON 구조가 어떻게 생겼는지 확인하고, 전날 산출물과 포맷을 비교한다. 이 단계가 충분해야 Write 단계가 정확하게 동작한다.

Write 전 Bash는 낭비가 아니다. 포맷이 맞지 않은 채로 Write하면, 결과물을 수정하거나 다시 쓰는 비용이 더 든다. 10번이라는 숫자가 단순히 "아무 결과도 없었다"는 뜻이 아니다. 탐색 단계에서 소비된 비용이다.

## raw JSON에서 카드뉴스 후보까지

이 세션의 목표는 `2026-05-28-daily-intel-raw.json`에서 두 유형의 콘텐츠 후보를 추출하는 것이었다.

- 일반용: AI 전반을 이해하는 카드뉴스형 콘텐츠
- 전문가용: 서비스 기획자·개발자 대상 인텔리전스 콘텐츠

출력은 두 파일로 정의됐다.

```
/Users/jidong/spoonai/crawl/newsite/2026-05-28-daily-intel.md
/Users/jidong/spoonai/crawl/newsite/2026-05-28-daily-intel.json
```

프롬프트 구조는 Socratic Scope Gate 형식이었다. 목표·범위·실제 작업·하지 않을 작업·가정을 명시한 구조다.

```
1) 이해한 목표: SpoonAI 새 사이트용 2026-05-28 Daily AI Intel 후보를 수집.
2) 범위/대상: 2026-05-28-daily-intel-raw.json만 근거로 사용.
3) 실제 작업: raw 후보를 선별·정리해 .md + .json 생성.
4) 하지 않을 작업: 기존 파이프라인 수정 없음.
```

이 형식을 쓰면 Claude가 "이게 맞나요?" 루프 없이 바로 실행에 들어간다. 하지만 이 세션에서는 Write 단계까지 도달하지 못했다.

## 왜 파일 생성까지 못 갔을까

가능성은 두 가지다. JSON이 예상보다 복잡해서 탐색 비용이 과도하게 쌓였거나, 세션 컨텍스트 한도에 도달했거나.

전날인 5월 27일 세션 1과 비교하면 차이가 보인다. 5월 27일에는 동일한 SpoonAI raw JSON 작업에 32 tool calls를 썼고 2분 만에 두 파일을 생성했다. 오늘은 10 tool calls에서 멈췄다.

10번이면 구조 파악 단계에서 끝났다는 뜻이다. Bash로 확인만 하다 세션이 닫혔다. 그 다음 실행 단계가 없었다.

이런 세션에서 배울 점이 있다. 탐색 후 실행이 분리되는 패턴은 연속 실행보다 비효율적이다. Bash로 구조를 파악한 컨텍스트가 쌓인 다음, 그 컨텍스트 위에서 바로 Write로 이어지는 게 이상적이다. 세션이 탐색 단계에서 끊기면, 다음 세션은 다시 탐색부터 시작한다.

## Socratic Gate가 있어도 탐색 비용은 든다

프롬프트에 범위와 목표를 명시했다. 그래도 탐색은 발생했다. 이유는 간단하다 — 프롬프트에는 "무엇을 만들어라"가 있지만, "지금 파일 구조가 어떻게 생겼는지"는 없다.

Claude가 Write 전에 확인하는 것들이 있다.

- 출력 디렉토리가 존재하는가
- 이전 날짜 파일의 포맷이 어떻게 생겼는가
- raw JSON의 최상위 키 구조는 무엇인가
- 전날 `.json` 산출물의 스키마는 어떻게 됐는가

이것들은 프롬프트가 해결해주지 않는다. 실제로 파일을 읽어봐야 안다. 이 비용이 Bash 10번으로 표현됐다.

해결책은 두 가지 방향이다. 하나는 이전 산출물 경로와 샘플을 프롬프트에 직접 포함하는 것. 다른 하나는 포맷 레퍼런스를 고정 경로에 두고 매번 거기서 읽게 하는 것. 둘 다 "다음 세션이 구조 파악을 건너뛰게" 하는 사전 투자다.

## 자동화 파이프라인의 관리 비용

SpoonAI daily intel은 매일 raw JSON이 생성된다. 이걸 받아서 `.md`와 `.json`으로 정제하는 작업이 매일 반복된다. 오늘처럼 탐색 단계에서 끊기면, 그날의 인텔 파일은 다음 세션에서 다시 만들어야 한다.

이 비용이 쌓이지 않으려면 파이프라인에 체크포인트가 필요하다. 탐색 결과를 파일로 저장하고, 다음 세션이 탐색을 반복하지 않도록 하는 구조다.

```
탐색 결과 → checkpoint.json 저장
다음 세션 → checkpoint.json 읽고 바로 Write 단계로 진입
```

5월 27일 세션 6-7에서 효과가 검증된 `brief.md` 패턴과 같은 원리다. 탐색 비용을 사전 지불하면, 실행 단계가 짧아진다.
