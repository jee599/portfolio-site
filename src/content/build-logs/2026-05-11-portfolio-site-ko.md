Bash 한 줄이 세션 전체를 멈췄다. `source ~/.claude/workflows/.../lib/state.sh` — state 헬퍼를 불러오는 코드다. 이게 훅에 걸렸고, 같은 응답에 묶인 Read 호출 4개가 연달아 취소됐다. 재시도도 같은 이유로 막혔다. 12 tool calls 끝에 수정 파일은 0개였다.

**TL;DR** 오케스트레이션 시스템의 PreToolUse 훅이 Bash 실행을 차단하면서, 병렬로 묶인 Read 호출까지 함께 취소됐다. 도구 통계: Read(8), Bash(4). 산출물 없음.

## 세션이 시작된 맥락

의료/치과 광고 일일 리서치 작업이었다. 목표는 SERP 데이터 요약본 4개 파일을 읽고, 기존 지식베이스에 추가할 핵심 변경점을 15줄 이내로 제안하는 것이다.

읽으려 했던 파일:

- `sources/serp-2026-05-11/summary.json`
- `2026-05-10-daily-update.md`
- `rolling-knowledge-base.md`
- `source-index.md`

간단한 읽기 작업처럼 보인다. 그러나 오케스트레이션 워크플로가 활성화된 상태였고, 첫 응답에서 Bash(`state.sh` source)와 Read 4개를 동시에 묶어 보냈다.

## 무슨 일이 일어났나

오케스트레이션 시스템은 `state.json` 업데이트를 요구한다. stage를 `implementing`으로 올리는 코드가 Bash 호출로 들어갔다. 훅이 이 Bash를 차단했다.

Claude Code의 동작 방식상, 하나의 응답에 포함된 병렬 도구 호출은 하나라도 실패하면 나머지도 취소될 수 있다. Read 4개가 Bash 차단의 부수 피해로 함께 날아갔다.

재시도도 같은 구조로 묶였고, 같은 이유로 막혔다.

세 번째 사용자 메시지에서 지시가 바뀌었다: "이전 요청의 결과만 15줄 이내로 출력해줘. 더 이상 파일을 읽지 말고 지금까지 읽은 내용으로 요약."

파일을 한 번도 읽지 못했으므로 요약할 내용이 없었다.

## 도구 분포

| 도구 | 횟수 | 결과 |
|---|---|---|
| Read | 8 | 전부 취소 |
| Bash | 4 | 전부 차단 또는 취소 |

총 12 tool calls. 유효한 결과: 0.

## 왜 이런 구조가 됐나

오케스트레이션 시스템은 모든 작업을 `trivial / simple / standard / major`로 분류하고, 단계별로 stage 상태를 기록하도록 설계됐다. state.sh 헬퍼가 stage를 갱신하는 역할을 한다.

`simple` 등급 작업이라도 workflow context가 주입되면 state 업데이트 코드가 따라붙는다. 문제는 Bash 실행 권한이 좁게 설정된 환경에서 이 코드가 차단된다는 점이다.

Read-only 작업인데도 Bash가 묶이면 전체가 멈춘다. 파일을 읽는 것 자체는 아무런 위험이 없지만, state 헬퍼 호출이 같은 응답에 들어가 있으면 함께 막힌다.

## 실질적인 수정 방향

같은 상황이 반복되지 않으려면 두 가지 중 하나다.

첫째, `trivial` 등급 분류를 더 정확하게 한다. 코드 변경 없는 파일 읽기 + 요약은 `trivial`이고, state 업데이트 코드가 붙지 않아야 한다. 오케스트레이션 라우팅 로직이 이 케이스를 잘못 분류했다.

둘째, Bash와 Read를 같은 응답에 묶지 않는다. state 헬퍼 호출을 먼저 보내고, 성공한 다음 Read를 보내면 연쇄 취소가 없다. 순차 의존성이 있는 호출을 병렬로 묶은 게 근본 원인이다.

## 기록하는 이유

세션 결과물이 없어도 빌드 로그를 쓴다. 실패한 세션이 정상 세션보다 더 많은 걸 알려주기 때문이다.

오케스트레이션 시스템이 자기 자신을 막을 수 있다는 것, Bash 하나가 Read 여러 개를 연쇄 취소할 수 있다는 것, trivial 분류가 정확하지 않으면 단순 읽기 작업도 실패한다는 것. 이 케이스들은 코드를 봐서는 알 수 없다. 실제로 막혀봐야 보인다.
