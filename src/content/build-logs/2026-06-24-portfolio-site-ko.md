"지금 결제 paddle이 아니라 paypal 아니야?"

스크린샷을 보내왔다. `PaddleBuy` 컴포넌트를 붙였는데 여전히 PayPal 버튼이 렌더링되고 있었다. 23시간 40분, 271 tool calls째였다. 지난 8세션 933 tool calls의 작업 기록을 정리한다.

**TL;DR** Paddle 결제 연동이 이번 주 최대 세션(271 tool calls)이었다. 나란히 코드잇 경쟁사 분석, 정부지원사업 42건 실측, 대학 185곳 콜드메일 자동화가 돌았다. Dynamic Workflow가 리서치를 위임받고, Claude가 구현을 직접 했다.

## PayPal → Paddle: geo 라우팅 버그가 숨어있던 곳

세션 2(23시간 40분, 271 tool calls)는 Bash 68회, 크롬 직접조작 67회, Edit 36회로 이루어졌다.

preterview에는 이미 `feat/geo-payment-routing` 브랜치가 머지된 상태였다 — 한국 → PayApp(₩), 해외 → PayPal($). Paddle은 Merchant-of-Record(부가세·VAT를 Paddle이 직접 처리)라 해외 경로를 통째로 교체하면 됐다.

Claude가 코드 작성 전에 Paddle Billing 공식 문서를 먼저 검증했다. "Paddle Billing API는 자주 바뀌고 웹훅 서명 검증을 틀리면 치명적이다." 웹훅 서명 검증, `Paddle.js` 초기화 방식, 크레딧 멱등 적립 패턴을 확인하고 나서 구현에 들어갔다.

생성된 파일:

- `lib/payments/paddle.ts` — configure/create/capture/verifyWebhook
- `app/api/pay/paddle/create/route.ts`, `webhook/route.ts`, `confirm/route.ts`
- `components/pricing/PaddleBuy.tsx`
- `app/[locale]/pricing/success/page.tsx`
- `docs/paddle-setup.md`

중반에 스크린샷이 왔다. `PaddleBuy` 컴포넌트가 붙어 있는데 PayPal 버튼이 나왔다. `lib/geo.ts`의 분기 조건이 뒤집혀 있었다. 해외 트래픽이 여전히 `paypal`로 라우팅됐다. 수정 후 sandbox에서 결제 완료 → 웹훅 수신 → 크레딧 적립 전 흐름을 크롬으로 실측했다.

같은 세션에서 stop hook이 2번 걸렸다.

```
Found 2 debug/T​ODO leftover(s) in working tree.
```

정리 후 "관련해서 모든 기능이 제대로 동작하는지, 사이드 이슈는 없는지 다차원적으로 파악해봐." 워크플로우가 Paddle 변경이 기존 PayApp·어드민 환불·payments 테이블에 미치는 영향을 적대적으로 검토했다. 결론: `feat/paddle-checkout`이 아직 main에 미머지라 prod 장애 없음.

## 경쟁사 분석: 4개 에이전트가 동시에 돌면

세션 4(22시간 37분, 168 tool calls)는 "코드잇에서 낸 내 프리터뷰랑 비슷한 기능이 있는 것 같은데 지금 기준 비교해줘"로 시작했다.

코드잇 어센트(AI 모의면접 서비스, 6일 전 출시). 워크플로우 4갈래가 동시에 실행됐다: 어센트 제품 정밀조사 / 코드잇 회사·전략 / 국내 경쟁 지형 / 핵심 주장 5건 교차검증.

교차검증에서 뒤집힌 클레임이 하나 있었다. "어센트에 GitHub·포트폴리오 URL 분석 기능 있음" — 실측 결과 없음(refuted). 확정된 사실: 어센트는 영상+음성 양방향, 전 직군(기업맞춤 면접 ~113개), 한국어 전용. preterview와 겹치는 건 "음성 양방향 + 다차원 리포트" 골격뿐. 정면충돌이 아닌 인접 시장.

바로 이어진 질문: "우리가 더 낫게하고 잘 팔리려면 어떻게 해야 돼." 워크플로우 두 번째. 글로벌 경쟁사(Final Round AI·interviewing.io) 파악 + GTM 채널·가격 조사 → 초안 → 3렌즈 자가비판(뻔하지 않냐 / 1인이 가능하냐 / 진짜 팔리냐). 결과: "8주 안에 첫 결제 N건" 가설 중심 실행계획.

같은 세션에서 로깅 시스템도 만들어졌다. "이력서랑 포폴 올리는거 구현되어 있어? 안된다고 하던데." Claude가 직접 테스트했다. 됐다. 그런데 "안된다고 피드백이 왔는데"라는 말이 이어졌다. 재현 시도. 이번엔 안 됐다. 로그가 없어서 어디서 죽었는지 알 수 없었다.

설계를 뽑는 워크플로우를 먼저 돌렸다. `app/api/client-log/route.ts`, `components/action-logger.tsx`, `lib/clientEvents.ts`, `app/admin/logs/page.tsx`, `app/api/admin/logs/export/route.ts`가 만들어졌다. 버튼 클릭·파일 선택·API 성공/실패를 DB에 쌓고 어드민에서 조회한다.

## 42건 지원사업, 이틀 뒤에도 한 번 더 검증

세션 5(2시간 44분, 51 tool calls): "지금 프리터뷰 / 치과 광고대행프로젝트로 지원할 수 있는 핏한 정부·민간 지원사업 모두 찾고, 링크·통과확률까지."

`~/funding/`에 6/21 마스터 리포트가 이미 있었다. 기존 자료를 토대로 18개 에이전트가 42건을 오늘 날짜 기준 라이브 검증했다. 1인 사업자 자격·마감·실제 지원 URL을 실측했다. 마감 임박 건: 프라이머 29기 6/28, K-Global 6/30, NPU 6/29.

세션 7(2시간 52분, 67 tool calls): "지금 기준으로 심플하게 ... 객관적인 사실 기준으로." 이틀 사이 공고 상태가 바뀐다. 18개 에이전트가 다시 팬아웃했다 — 14건 재검증 + 4건 갭 스윕. 판교밸류업이 dental 부적합으로 확정됐고, MS AI 바우처는 대행 제외로 확인됐다. 핵심 결론: 트랙션 0 1인 사업자의 현실 승부처는 무지분(멘토링·인프라·크레딧·융자, 통과율 40~85%). 지분 시드/AC는 한 자릿수.

## 대학 185곳 콜드메일, 개인화된 채로

세션 8(27시간 53분, 290 tool calls)이 tool calls 기준 최대 세션이었다.

preterview를 IT 교육기관에 영업하기 위해 국내 72곳 + 국외 113곳 합계 185개 기관의 공개 이메일을 실측 수집했다. "추측 이메일 금지"가 제약 조건. 웹에서 확인된 주소만, 없으면 `noEmail` 처리.

각 기관 특성에 맞춘 개인화 콜드메일 초안이 함께 만들어졌다. 삼성SW아카데미와 MIT CSAIL과 연세대 취업지원센터는 톤과 강조점이 달라야 한다. 최종 산출물: CSV 하나에 기관명·공개 이메일·국내외 구분·개인화 초안 전문.

중간에 이메일 영상 첨부 문제가 계속 발목을 잡았다. "▶ 30초 데모 영상 — 클릭하면 재생됩니다" 버튼이 이메일 클라이언트에서 계속 작동하지 않았다. 영상 자동재생은 대부분의 이메일 클라이언트가 차단한다. 결국 GIF 프리뷰 + 링크 방식으로 바꿨다. 크론잡으로 하루 30건씩 throttle 발송하는 구성까지 붙였다.

## 번외: 이사도 Claude Code로

세션 3(1시간 3분, 79 tool calls)은 봇들마을 24평 + 봇들마을 32평을 트리니원 34평으로 합치는 이사였다. 업무 컨텍스트가 아니다.

가전 결정표 CSV(냉장고·세탁기 등 31개 품목), 가구 결정표 CSV, 통신·행정 체크리스트 CSV(40항목)를 만들고, 거기서 "사이트로 배포해줘"로 확장됐다. 가져가기·팔기·버리기 탭을 누르면 집계가 실시간 갱신되고 `localStorage`에 저장되는 HTML 앱. Vercel Blob API로 서버 사이드 싱크까지 붙였다.

솔로 스타트업에서 업무와 개인이 섞인다. Claude Code는 그 경계를 구분하지 않는다.
