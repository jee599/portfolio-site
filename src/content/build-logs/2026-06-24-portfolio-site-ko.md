"안 된다고 피드백이 왔는데, 로그인하라는 알람이 안 떠?"

재현이 안 됐다. 직접 테스트했더니 업로드가 됐다. 어느 단계에서 실패했는지, 어떤 에러가 발생했는지 추적할 방법이 없었다. 이게 이번 주 세션 중 가장 좋은 기억이 남은 순간이다. 3일, 10세션, 924 tool calls의 작업 기록을 정리한다.

**TL;DR** "안 된다"는 피드백 하나가 클라이언트 행동 로깅 시스템으로 이어졌다. 나머지 세션은 Paddle 결제 통합, 경쟁사 분석, 광고 픽셀, 지원사업 서치였다. Dynamic Workflow가 리서치를 위임받았고 Claude가 직접 구현했다.

## "안 된다"는 피드백을 재현할 수 없을 때

세션 4(22시간 37분, 168 tool calls)에서 이 교환이 있었다.

> "이력서랑 포폴 올리는거 구현되어 있어? 안된다고 하던데"

Claude가 직접 테스트했다. 됐다. 그러자 이어진 말:

> "안된다고 피드백이 왔는데, 로그인하라는 알람이 안 떠?"

"너가 해봐"라고 했다. 재현 시도. 이번엔 안 됐다. 업로드 버튼은 눌렸는데 아무것도 일어나지 않았다. 로그가 없어서 어디서 죽었는지 알 수 없었다. `디지텍`이라는 특정 사용자의 케이스였다.

그 지점에서 방향이 정해졌다. "고쳐줘"가 아니라 먼저 로깅 시스템을 만들어야 했다. 워크플로우를 하나 돌려서 설계를 뽑았다.

설계 결론: `client-log` API 라우트 + `action-logger.tsx` 컴포넌트. 버튼 클릭·파일 선택·API 호출 성공/실패를 DB에 쌓고, 어드민에서 조회할 수 있게 한다. 생성된 파일: `app/api/client-log/route.ts`, `components/action-logger.tsx`, `lib/clientEvents.ts`, `app/admin/logs/page.tsx`, `app/api/admin/logs/export/route.ts`.

이후 stop hook이 걸렸다.

```
Found 1 debug/TODO leftover(s) in working tree.
```

커밋 전에 디버그 잔재를 잡아내는 훅이다. 정리 후 "너 작업물 중에 불필요하거나 영향을 받는 사이드 이슈 나는거 없는지 확인해"라고 했다. 워크플로우가 돌았다 — 클라이언트 로깅이 기존 API 라우트·미들웨어·번들 크기에 미치는 사이드이펙트를 적대적으로 검토했다. 결론: 로깅 자체는 이슈 없음, 다만 아직 `feat/paddle-checkout` 브랜치가 main에 미머지 상태라 prod 장애 없음.

## Paddle 결제: 67번 브라우저 직접 조작

세션 2(23시간 40분, 271 tool calls)가 도구 호출 기준 가장 무거웠다.

"paddle 결제 perterview에 붙일거야"로 시작했다. 프리터뷰에는 이미 `feat/geo-payment-routing` 브랜치가 머지돼 있었다 — 한국 → PayApp(₩), 해외 → PayPal($). Paddle은 Merchant-of-Record라 해외 경로만 교체하면 됐다.

Claude가 구현 전에 먼저 Paddle 공식 문서를 검증했다. 이유가 명확했다. "Paddle Billing API는 자주 바뀌고 웹훅 서명 검증을 틀리면 치명적이라 구현 전에 공식 문서로 현재 통합 방식을 정밀 검증."

`mcp__claude-in-chrome__computer`가 67번 호출됐다. Claude가 Paddle 대시보드를 직접 조작했다. 제품 생성, Price 3종 설정, API 키·웹훅 시크릿 발급, 웹훅 엔드포인트 등록, 샌드박스 결제 테스트까지. 중간에 이 메시지가 왔다.

> "지금 결제 paddle이 아니라 paypal 아니야?"

브라우저 스크린샷을 확인했더니 `PaddleBuy` 컴포넌트 대신 `PayPalBuy`가 렌더링되고 있었다. geo 라우팅 조건 분기 버그였다. `lib/geo.ts`를 수정했다. 생성된 파일: `lib/payments/paddle.ts`, API 라우트 3개(create/webhook/confirm), `components/pricing/PaddleBuy.tsx`, `docs/paddle-setup.md`.

"크레딧 충전되면 충전됐다는 페이지로 넘어가는게 나을 것 같은데?"라는 피드백도 같은 세션에서 나왔다. `app/[locale]/pricing/success/page.tsx`가 이때 만들어졌다.

## 경쟁사 분석을 27시간 35분에 하면

같은 세션 4에서, 그리고 별도로 세션 9(27시간 35분, 267 tool calls)에서 경쟁사 분석과 광고 소재 작업이 겹쳤다. 세션 4는 코드잇 어센트 비교가 시작이었다.

코드잇이 AI 모의면접 서비스 '어센트(Ascent)'를 6일 전에 냈다. "코드잇에서 낸 내 프리터뷰랑 비슷한 기능이 있는 것 같은데 지금 기준 비교해줘." 워크플로우가 4갈래로 팬아웃했다. 어센트 제품 정밀조사 / 코드잇 회사·전략 맥락 / 국내 경쟁 지형 / 핵심 주장 5건 교차검증.

검증에서 중요한 반박 하나: "어센트에 GitHub/포트폴리오 URL 분석 기능 있음"이라는 클레임이 refuted였다. 없다. 실측으로 확정된 것: 어센트는 영상+음성 양방향, 전 직군(~113개 기업맞춤 면접), 한국어 전용. 프리터뷰의 개발자 특화·글로벌·GitHub 연동과 겹치는 건 "음성 양방향 + 끝나고 다차원 리포트" 골격 정도였다. 정면충돌이 아닌 인접 시장이라는 결론.

그 바로 다음 질문: "우리가 더 낫게하고 잘 팔리려면 어떻게 해야 돼." 워크플로우 두 번째. 프리터뷰 실제 코드 빈틈 + 글로벌 경쟁사(Final Round AI·interviewing.io) 파악 + GTM 채널·가격 조사 → 초안 → 3렌즈 자가비판(뻔하지 않냐 / 1인이 가능하냐 / 진짜 팔리냐). 결과는 "8주 안에 첫 결제 N건" 가설 중심의 실행계획이었다.

## 네이버 파워링크 카피 15자의 무게

세션 7(23시간 25분, 76 tool calls)의 구조가 독특했다. 질문이 단계적으로 좁아지면서 워크플로우가 3번 순차로 돌았다.

1차: "인스타가 나아? 얼마를 어떤 타겟에 태우는게 가장 효과적인지 객관적인 수치랑 근거로 서칭해줘. 국내·글로벌 모두." → 24개 에이전트, ~880k 토큰, 245번 웹 도구. 13개 주요 수치가 검증 후 수정됐다.

2차: "해줘 1, 2, 3" → 네이버 파워링크 셋업, Reddit 광고 소재 3개, 픽셀+랜딩 체크리스트를 플랫폼 제약에 맞게 QA 검증하면서 생성.

3차: "예산 한 50만원으로 잡고 싶어" → 채널별 50만 원 배분 시 예상 도달 퍼널 모델.

이 과정에서 네이버로 좁혀진 뒤 추가 워크플로우가 실제 월간 검색량 + CPC 기반 가성비 키워드를 뽑았다. 최종: 네이버 파워링크 제목 15자 제약에 맞는 광고 카피가 키워드 그룹별로 나왔다. 면접말버릇·면접습관교정·AI면접·개발자면접 그룹으로 나눠서.

픽셀 구현은 Claude가 직접: `components/marketing/analytics-scripts.tsx`(네이버·GA4 스크립트 로드), `lib/marketing/consent.ts`(GDPR 동의 상태), `lib/marketing/conversions.ts`(전환 이벤트), `lib/marketing/track.ts`(래퍼). GA4 측정 ID `G-ES6SENFGM2`와 Paddle 결제 성공 페이지를 연결했다.

## 42건 지원사업 검증, 이틀 뒤 재검증

세션 5(2시간 44분, 51 tool calls)와 세션 8(1시간 36분, 5 tool calls)이 연결된다.

세션 5: "지금 프리터뷰 / 치과 광고대행프로젝트로 지원할 수 있는 핏한 정부·민간 지원사업 모두 찾고." 이미 `~/funding/`에 6/21 마스터 리포트가 있었다. 쌓인 자료를 토대로 워크플로우가 42건을 라이브 검증했다. 마감 임박 건: 프라이머 29기 6/28, K-Global 6/29, 삼성 C-Lab 6/26.

이틀 뒤 세션 8: "지금 기준으로 심플하게 ... 서칭해서 지원방법이나 링크, 통과확률 간단하게." 지원사업 공고는 이틀 사이에도 바뀐다. 18개 에이전트가 14건 재검증 + 4건 갭 스윕으로 팬아웃했다. "재조사가 아니라 오늘(6/24) 기준 아직 살아있는 것만 추려 재정리"가 방향이었다.

## 번외: 2집 → 1집 이사도 Claude Code로

세션 3(1시간 3분, 79 tool calls)은 완전히 다른 맥락이었다. 봇들마을 3단지 24평 + 봇들마을 1단지 32평을 트리니원 34평으로 합치는 이사.

"체크해야하는 것들 / 가전 어디꺼 쓸지 ... 엑셀이나 다른 체크 리스트처럼 해서"로 시작해서 "사이트로 만들어서 배포해줘. 내용 저장되게 해줘."까지 세 단계로 확장됐다.

가전 결정표 CSV(31개 품목), 가구 결정표 CSV, 통신·행정 체크리스트 CSV(40항목). 그리고 인터랙티브 앱 — 가져가기·팔기·버리기 탭을 누르면 집계가 실시간 갱신되고 `localStorage`에 저장되는 HTML 앱을 빌드했다. design gate가 걸렸다가 OD-equivalent 디자인 패스 사유로 통과됐다. Vercel Blob API로 서버 사이드 상태 싱크까지 연결했다.

솔로 스타트업에서 업무 컨텍스트와 개인 생활이 자연스럽게 섞인다. Claude Code는 그 경계를 구분하지 않는다.
