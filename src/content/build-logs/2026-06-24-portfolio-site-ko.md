72시간 동안 7개 세션을 열고 Claude Code가 도구를 839번 호출했다. 경쟁사 분석, 정부지원사업 리서치, 영업 메일 제작, Paddle 결제 통합, 광고 픽셀 설치, 심지어 이사 체크리스트 앱까지. 솔로 스타트업이 한 주치 업무를 어떻게 압축했는지 기록한다.

**TL;DR** Dynamic Workflow(멀티에이전트 팬아웃)가 이 72시간의 핵심 패턴이었다. 복잡한 리서치는 워크플로우로 위임하고, 구현은 직접. 839 tool calls 중 Bash 286번·Edit 123번·Read 95번이 핵심 삼각형이다.

## Dynamic Workflow가 일상이 됐다

세션마다 반복되는 구조가 있었다. 복잡한 질문이 들어오면 Claude가 직접 답하는 대신 Dynamic Workflow를 띄운다. 에이전트 수십 개가 병렬로 웹서치·코드 분석·교차검증을 돌리고, 완료되면 `<task-notification>`이 돌아온다.

실제 사례: "preterview 광고 태우려고 하는데 인스타가 나아? 얼마를 어떤 타겟에 태우는 게 가장 효과적인지 객관적인 수치랑 근거로 서칭해줘. 국내·글로벌 모두." 이 한 줄에 워크플로우가 24개 에이전트를 돌렸다. 5개 리서치 에이전트가 네이버·메타·구글·레딧·틱톡 채널별 실측 벤치마크를 병렬 수집하고, 17개 검증 에이전트가 숫자의 신뢰도를 따졌다. 결과: 13개 주요 수치가 수정되거나 반박됐다. 약 880k 토큰, 245번 웹 도구 호출.

리서치 성격의 질문은 전부 이 방식이었다. 이번 주 워크플로우가 돌아간 횟수만 세어도 7번이 넘는다.

## 코드잇 어센트를 하루 안에 해부했다

6월 17일 코드잇이 AI 모의면접 서비스 어센트(Ascent)를 냈다. 프리터뷰와 정면으로 겹치는 영역이다. 조사 시점 기준 6일 전 출시였다.

"코드잇에서 낸 내 프리터뷰랑 비슷한 기능이 있는 것 같은데 지금 기준 비교해줘"라고 던졌다. 워크플로우가 4갈래로 팬아웃했다. 어센트 제품 정밀조사, 코드잇 회사·전략 맥락(KADE·왓타임 인수), 국내 AI 모의면접 경쟁 지형, 핵심 주장 5건 교차검증.

검증에서 중요한 반박이 하나 나왔다. "어센트에 GitHub/포트폴리오 URL 분석 기능 있음"이라는 주장이 refuted — 없다. 실측으로 확정된 것: 어센트는 영상+음성 양방향, 전 직군(~113개 기업맞춤 면접), 한국어 전용. 프리터뷰가 개발자 특화 글로벌·GitHub 연동인 것과 달리, 어센트는 국내 전 직군이라 정면충돌이 아닌 인접 시장이라는 결론이 나왔다.

세션 전체 163 tool calls, Bash 50번·Read 17번·Edit 14번.

## Paddle 결제 통합: 271번의 도구 호출과 브라우저 자동화

가장 무거운 세션은 Paddle 결제 통합이었다. 23시간 40분, 271 tool calls. 프리터뷰는 이미 한국 PayApp + 해외 PayPal로 geo 라우팅이 구현돼 있었다. Paddle은 Merchant-of-Record라 해외 경로 대체가 자연스러웠다.

Claude가 먼저 공식 문서로 현재 통합 방식을 검증했다. "Paddle Billing API는 자주 바뀌고 웹훅 서명 검증을 틀리면 치명적"이라는 이유였다. 검증 후 생성된 파일: `lib/payments/paddle.ts`, `app/api/pay/paddle/create/route.ts`, `app/api/pay/paddle/webhook/route.ts`, `app/api/pay/paddle/confirm/route.ts`, `components/pricing/PaddleBuy.tsx`. 기존 PayPal 코드는 보존하되 노출만 끈 구조다.

이 세션에서 `mcp__claude-in-chrome__computer`가 67번 호출됐다. 대시보드에서 Price ID 복사, 웹훅 엔드포인트 등록, 샌드박스 결제 테스트를 Claude가 브라우저를 직접 조작해 처리했다. 중간에 "지금 결제 paddle이 아니라 paypal 아니야?"라는 피드백이 왔고, 브라우저 스크린샷 확인 후 라우팅 로직 버그를 잡아 수정했다.

## 광고 픽셀 설치와 50만 원 예산 배분

광고 전략 세션(8시간 46분, 69 tool calls)은 질문이 단계적으로 좁혀지는 구조였다. "인스타가 나아?" → "50만 원으로 잡고 싶어, 트렌디하게" → "픽셀이 뭐야?" → "네이버로 하자, 가성비 좋은 키워드 찾아봐봐."

워크플로우가 순차로 세 번 돌았다. 채널·타겟·예산 리서치 → 네이버 파워링크 셋업·광고 카피·픽셀 체크리스트 생성 → 채널별 예산 대비 예상 도달 퍼널 모델. 네이버로 결정된 후 추가 워크플로우가 실제 월간 검색량 + CPC 기반 가성비 키워드를 뽑았다.

픽셀 구현은 Claude가 직접 했다. `components/marketing/analytics-scripts.tsx`(네이버 클릭초이스 픽셀 + 구글 gtag 로드), `lib/marketing/consent.ts`(GDPR 동의 상태 관리), `lib/marketing/track.ts`(전환 이벤트 래퍼). 어드버타이저 스크립트를 Next.js `layout.tsx`에 심고, 전환 이벤트를 Paddle 결제 성공 페이지와 연결했다.

## stop hook이 두 번 커밋을 막았다

세션 4와 세션 7에서 커밋 직전 stop hook이 걸렸다.

```
Stop hook feedback:
Found 2 debug leftover(s) in working tree.
```

디버그 로그 잔재와 임시 주석을 감지해 커밋 전에 차단하는 훅이다. 세션 4에서는 이메일 HTML 작업 중 남은 디버그 코드, 세션 7에서는 픽셀 구현 중 임시 주석이 걸렸다. 매번 "관련해서 모든 기능이 제대로 동작하는지 / 사이드 이슈는 없는지 다차원적으로 파악해봐"라는 요청으로 이어졌고, Claude가 변경 범위 전체를 훑어 정리한 뒤 커밋했다.

design gate도 반복됐다. 이사 체크리스트 앱 HTML, 영업 페이지, 이메일 템플릿을 만들 때마다 걸렸다. 게이트를 열려면 Open Design 패스 사유를 명시해야 한다. preterview 세션에서는 `globals.css`의 verbatim 토큰을 바인딩했다는 이유로 통과했다.

## 번외: 이사 체크리스트 앱도 Claude Code로

세션 5(1시간 3분, 79 tool calls)는 완전히 다른 맥락이었다. 2집 짐을 합쳐 트리니원 34평으로 이사하는 결정 지원 도구. "사이트로 만들어서 배포해줘. 내용 저장되게 해줘."

가전 결정표 CSV, 가구 결정표 CSV, 통신·행정 체크리스트 CSV를 만들고, 인터랙티브 앱(가져가기·팔기·버리기 분류, 집계 실시간 갱신, localStorage 자동저장)을 HTML로 빌드해 배포했다. 솔로 스타트업의 업무 컨텍스트에 개인 생활이 자연스럽게 섞이는 Claude Code 사용 패턴이다.
