하루 4개 프로젝트, 4세션, 643번의 도구 호출. 그중 하나만 365 tool call이었다.

세션 3이 25시간 48분이 걸렸다. AI 취업 준비 SaaS "커피챗"의 모바일 UI 점검에서 시작해서 크레딧 시스템, 어드민 페이지, 결제 연동, 이메일 인증, 아이콘까지 전부 갈아엎었다.

**TL;DR** 크레딧 단가를 역산하는 데만 1시간이 걸렸다. 병렬 workflow는 사주 프로젝트 시장 분석처럼 독립 단위가 많을 때 실질적으로 빠르다. 같은 날 치과 리디자인은 Open Design 루트 — 레퍼런스 리서치부터 방향 선택까지 코드 전에 먼저.

## 25시간 세션, Edit 81회, Bash 113회

커피챗 세션의 시작 프롬프트: "커피챗 프로젝트 현상황 / 남은 작업 확인해줘 그리고 모바일에서 열었을 때 UI 고려해줘."

전수 감사가 필요한 케이스라 workflow를 띄웠다. 상태 점검 2개(빌드/헬스 + 기능 완성도) + 모바일 UI 감사 6개 표면(글로벌·내비 / 랜딩 / 이력서 / 포트폴리오 / 면접 / 계정·결제·대시보드·어드민) = 에이전트 8개 병렬로 돌았다.

감사 결과가 나오는 동안 dev 서버를 백그라운드로 띄워서 실제 390px 모바일 폭에서 교차 검증했다. 정적 코드 분석 + 실 렌더 결과를 동시에 보는 패턴이다. 그 이후가 진짜 무거운 작업이었다. 크레딧 시스템, 어드민, 글로벌 GTM 순으로.

## 크레딧 단가를 역산하는 데 1시간이 걸렸다

핵심 문제는 하나였다: 면접 30턴에 얼마를 받을 것인가.

> "이력서 / 포폴 / 면접 20/30턴, 보고서 각각 sonnet / opus로 했을 때 얼마가 들고, 내부 크레딧으로는 얼마가 소모돼?"

API 원가 → 크레딧 환산 → 유저 판매가 순으로 역산했다. 5배 마진을 적용하면 30턴 면접이 크레딧 기준 900이 나왔다.

> "30턴에 7000원 정도 나오게 하고 싶어."

크레딧 100개 = 1달러 기준으로 계산했을 때 30턴 = 900크레딧 = 9달러. 환율 적용하면 12,000원 선. 목표 7,000원에 못 미쳤다. 결론으로 선택한 건 Anthropic의 프롬프트 캐싱이었다. 시스템 프롬프트가 고정이라 반복 호출 원가가 최대 90% 줄어든다. `lib/credits.ts`에 캐싱 로직을 구현하고 30턴 900크레딧 = 7,000원 목표치를 맞췄다.

보너스 크레딧은 처음에 200으로 잡았다가 300으로 올렸다가 다시 200으로 내렸다. `lib/constants.ts`를 만들어 변수로 관리하지 않으면 300/200 문구가 코드 곳곳에 하드코딩됐을 거다.

## 어드민 + 이메일 인증 + 방문자 추적

> "admin 페이지 어디에 만들었어? 모든 유저들 동향 / 사용한 api 요금 유저별, 방문자 수, 각 기능별로 얼마나 사용했는지"

`lib/audit.ts`를 새로 만들고 `app/api/track/route.ts`로 각 기능 호출마다 사용량을 기록하는 구조를 추가했다. 어드민에서 유저별 크레딧 소비 + API 원가 + 기능별 사용률을 한 화면에서 볼 수 있게 됐다.

방문자 추적에는 별도 인프라가 필요했다. Resend API 키를 연결해서 이메일 인증을 붙이고(`app/api/auth/signup/route.ts`), `page-tracker.tsx`로 페이지뷰를 추적했다. 결제는 PortOne으로 결정했다. 토스는 해외 결제가 막혀있고, PortOne은 국내 PG + 해외 카드를 한 SDK로 처리한다.

글로벌 GTM 보고서도 같은 세션에서 나왔다: `~/reports/posts/2026-06-15-coffeechat-global-gtm.html`. 핵심 결론은 영어권으로 나가기 전에 국내에서 직군을 먼저 확장하는 편이 낫다는 거였다.

## 사주 프로젝트: 5개 병렬 분석 → X봇 구축

두 번째로 무거운 세션이 FortuneLab/사주 프로젝트였다. 142 tool call, 14시간 49분.

먼저 현황을 꺼냈다. `~/saju_global/STATUS.md`에서 실제 지표를 확인했다.

- 누적 유료 주문 30건 (전부 KR Toss, 해외 PayPal 0건)
- 4월 세션 87회
- 프로덕션이 44일 동안 배포가 끊겨 있었음

이 상태에서 "팔아야 돼, 전략 수립해줘"라는 요청이 왔다. 5개 에이전트를 병렬로 돌렸다: KR 시장 분석, 단위경제 분석, 제품 진단, 채널 분석, 자산 매각 전략. 5개 분석 결과가 같은 결론으로 수렴했다: 현재 트래션이 너무 얇다.

그래서 X봇을 만들었다.

> "x 계정에 영어로 6시간마다 사주 풀이 하는건 어때? 특정 타겟층 대상으로"

`lib/xbot/` 디렉토리에 7개 모듈이 생겼다. `cohorts.ts`(타깃 코호트), `formats.ts`, `viral.ts`, `voices.ts`, `rotate.ts`, `xClient.ts`, `generate.ts`. Vercel Cron으로 `/api/cron/x-post/route.ts`를 6시간 주기로 연결했다.

계정 브랜딩 이미지는 `gpt-image-2`로 세 번에 걸쳐 생성했다. 아바타·배너·페르소나를 여러 스타일로 뽑고 `x-brand/avatar-preview.html`로 비교했다.

## Claude Code 리서치 → GitHub Pages 보고서

58 tool call, 13시간 11분(대기 포함). 이 세션에서 직접 Edit은 3회뿐이다.

Opus 4.8 기준 Claude Code를 잘 쓰는 법을 공식문서 / GitHub 생태계 / 커뮤니티 트렌드 세 갈래로 나눠 에이전트 3개가 병렬로 돌았다. 결과를 종합해서 report-builder 스킬로 HTML 보고서를 GitHub Pages에 발행했다.

발행 경로: `~/reports/posts/2026-06-15-claude-code-opus-48-best-practices.html`

이후 Dynamic Workflow 부분을 따로 깊게 파달라는 요청이 왔다. 공식 문서 갈래 + 실전/예제 갈래로 나눠 추가 리서치 후 보고서에 섹션을 추가했다.

## 유디치과 리디자인: 코드 전에 레퍼런스 먼저

네 번째 세션은 1시간 3분, 78 tool call. 특이한 점은 `mcp__claude-in-chrome__computer`가 23회로 가장 많다는 거다. 화면 캡처와 브라우저 조작이 주였다는 뜻이다.

시작 요청: "전체적으로 AI 티 없고 상위권 치과의 디자인과 동일하거나 그것보다 예쁘게."

바로 코드를 고치면 안 되는 케이스였다. Open Design 루트로 들어갔다. 방향부터 먼저 잡았다: 홈 먼저 → 전체 롤아웃, 한국 상위권 치과 사이트 실측 리서치를 레퍼런스로, 프리미엄 사진중심 + 산세리프 모던 (명조·AI 티 배제).

유디치과 실제 자산(사진 13장: 외관/대기실/진료실/복도)을 먼저 파악하고, 상위권 치과 사이트 리서치를 에이전트 2개로 병렬로 돌렸다. 방향 후보를 HTML로 뽑아서 브라우저에 띄워 비교하는 게 목표였다. `home-preview.html`과 `directions-preview.html`이 이 단계의 산출물이다. 코드베이스 직접 수정은 그다음 단계였다.

## 병렬 workflow가 효과적인 조건

4세션을 돌아보면 패턴이 보인다. 전수 감사(커피챗 모바일 UI 8개 표면), 독립적인 시장 분석(사주 프로젝트 5개 축), 레퍼런스 리서치(치과 2개 갈래)는 전부 병렬로 돌았다. 각 단위가 서로 의존하지 않을 때다.

반대로 크레딧 단가 역산은 순차였다. 원가 → 마진율 → 크레딧 가격 → 보너스 조정으로 앞 결과가 다음 입력을 결정했다. 여기서 workflow는 도움이 안 된다. 직접 대화가 더 빠르다.

세션 성격이 다르면 도구 분포가 달라진다:

| 세션 | tool call | 지배 도구 |
|---|---|---|
| CoffeeChat | 365 | Bash 113, Edit 81, Read 76 |
| FortuneLab | 142 | Bash 35, Read 24, Write 19, Edit 17 |
| 유디치과 | 78 | Chrome 33, Edit 9, Bash 8 |
| Claude 리서치 | 58 | Bash 38, Agent 5, Read 3 |

전체 4세션: Bash 194회, Edit 110회, Read 108회, Write 41회. 수정 파일 41개, 생성 파일 36개.
