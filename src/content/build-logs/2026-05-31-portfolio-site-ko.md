오늘 Claude Code 세션 2개, tool call 총 31번. 하나는 SpoonAI 새 사이트에 넣을 콘텐츠 후보를 179개 크롤 데이터에서 추리는 작업이었고, 다른 하나는 의료·치과 광고 리서치 KB를 매일 누적하는 파이프라인이었다.

**TL;DR** Opus 4.8 2 세션으로 콘텐츠 인텔리전스 크론과 의료 광고 리서치 산출물을 각각 완료했다. 총 소요 4분, 생성/수정 파일 5개.

## SpoonAI 콘텐츠 인텔리전스 — 179개 크롤에서 후보 추리기

SpoonAI 새 사이트에는 두 종류의 콘텐츠가 들어간다. 일반용 카드뉴스형(8~15개)과 전문가용 AI 인텔리전스(10~20개). 원자료는 `2026-05-31-daily-intel-raw.json`이다.

프롬프트 구조는 명확했다.

```
목표: 새 SpoonAI 사이트에 넣을 일반용 카드뉴스형 AI 전반 이해 콘텐츠 후보와
     전문가용 AI 인텔리전스 후보를 오늘 raw crawl에서 선별·정리한다.
범위: 2026-05-31-daily-intel-raw.json을 읽고
     2026-05-31-daily-intel.md, .json만 작성한다.
제외: 발행 금지, 이메일 발송 금지
```

"발행 금지, 이메일 발송 금지"를 명시한 건 중요하다. 범위 밖 행동을 사전에 차단하는 가장 확실한 방법이다. LLM은 "당연히 발행까지 해주면 좋겠지"라는 추론을 하기 쉽다.

Claude가 제일 먼저 한 건 원자료를 읽기 전에 전날 출력 파일을 참조하는 것이었다. `general_angle`, `expert_notes`, `numbers`, `secondary_sources` 같은 필드 형태를 실제 산출물에서 역추적했다. 스키마를 프롬프트에 전부 적어 넘기는 방식이 아니라, "어제 네가 만든 파일과 같은 형태로 써라"가 더 정확하고 안정적인 이유가 여기 있다.

Read 3번, Bash 6번으로 tool call 9번. 소요 시간은 측정 불가 수준이다. 179개를 읽고 선별 기준을 적용해 구조화된 JSON까지 만드는 작업을 사람이 하면 반나절이다.

## 의료 광고 리서치: 12번 읽고 3번 쓰는 이유

두 번째 세션은 의료·치과 광고 데일리 리서치였다. 입력은 `serp-2026-05-31/summary.json`과 당일 수집 HTML, 출력은 `2026-05-31-daily-update.md` 생성과 누적 파일 4개 업데이트다.

총 22 tool call 중 Read가 12번이었다. 비율만 보면 이상해 보인다. 실제 쓰기(Edit 3번, Write 1번)보다 읽기가 세 배 많다. 순서를 보면 이렇다.

1. 디렉토리 구조 파악 (Bash)
2. 직전 날 `2026-05-30-daily-update.md` 포맷 확인 (Read)
3. `summary.json` 원자료 읽기 (Read)
4. 아티팩트 프롬프트 지침 읽기 (Read)
5. 누적 파일 4개 순차 읽기 — `rolling-knowledge-base.md`는 크기가 커서 tail 따로 읽음 (Read ×5)
6. `2026-05-30` HTML 리포트 스타일 확인 (Read)

이게 낭비처럼 보이지만 실제로는 반대다. `rolling-knowledge-base.md`는 며칠치 데이터가 누적된 파일이다. 포맷을 모르고 append하면 기존 항목과 일관성이 깨진다. KB가 30일치 쌓인 시점에 패턴 이탈을 발견하면 그걸 고치는 비용이 훨씬 크다.

> "12번 읽고 3번 쓴다"는 게 누적 파일 작업의 올바른 비율이다.

결과물은 `2026-05-31-daily-update.md` 신규 생성, `rolling-knowledge-base.md`와 `source-index.md` 업데이트. 4분 안에 끝났다.

## 크론 자동화에서 컨텍스트 체인이 중요한 이유

두 세션 다 공통 구조를 갖는다. 오늘 한 번으로 끝나는 게 아니라 내일도 돌아가는 크론이라는 것.

SpoonAI 인텔리전스 크론은 매일 `raw crawl → 선별 → .md/.json 출력` 루틴이다. 의료 광고 리서치는 매일 `SERP 데이터 → 일일 업데이트 → 누적 KB append` 패턴이다. 두 경우 모두 Claude가 이전 날 출력을 참고해서 오늘 것을 만든다. 사람이 포맷 지침을 매번 설명할 필요가 없다.

이 구조에서 프롬프트 디자인의 핵심은 "무엇을 만들라"보다 "어디서 참고하라"를 명시하는 부분이다. "이전 날 파일과 같은 구조로 써라"는 지침 하나가 스키마 문서 몇 페이지보다 안정적으로 동작한다. 누적 데이터가 쌓일수록 컨텍스트가 풍부해지고, 모델이 참고할 패턴도 많아진다.
