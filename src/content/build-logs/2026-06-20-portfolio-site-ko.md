실결제 후 크레딧이 0으로 표시됐다. 결제는 성공했는데 계정에 아무 변화가 없었다.

**TL;DR** PayApp 웹훅 `linkval` 검증 로직이 실제 PayApp 동작 방식과 달랐다. 프로덕션 시크릿이 로컬에 없어 직접 DB 조회가 불가능했고, Vercel 런타임 로그에서 에러 패턴을 찾아 해결했다.

## 결제는 됐는데 크레딧이 0

preterview.com은 AI 면접 시뮬레이터다. 크레딧을 구매하면 면접 세션을 진행할 수 있다. 결제 모듈은 PayApp — 심사 없이 링크만 보내면 되는 구조라 카카오페이 가맹 심사 대기 중에 빠르게 붙였다.

문제는 실결제 직후에 터졌다. 테스트 계정으로 직접 구매를 했는데:

```
크레딧 0이 충전됐어요!
```

알림 문구 자체가 버그였다. `0`이 충전됐다고 표시하면서 결제 성공이라는 문구가 떴다. Claude에게 상황을 넘겼다.

```
지금 결제 테스트 했는데 실결제 이후에 크레딧 안들어오는데?
```

## 로컬에 시크릿이 없다

Claude가 먼저 한 건 `.env.local` 확인이었다. 그런데 파일 안에:

```
APP_ORIGIN=https://preterview.com
```

Turso 연결 정보도, PayApp 시크릿도 없었다. 프로덕션 시크릿은 Vercel 환경 변수에만 있고, 실결제 데이터는 프로덕션 DB(Turso)에만 있었다. 로컬에서 직접 진단이 불가능한 구조.

Claude는 방향을 바꿔 Vercel MCP로 프로덕션 런타임 로그를 읽기 시작했다. `mcp__claude_ai_Vercel__get_runtime_logs`를 5번 호출했다.

## 런타임 로그에서 잡힌 패턴 2개

로그를 뒤지자 두 개의 패턴이 보였다.

**17:49** — `feedback 검증 실패(위조 가능)` → `linkkey`/`userid` 1차 검증에서 탈락. 그 시점엔 `/ready` 엔드포인트가 401을 반환했다.

**19:19 (최신 실결제)** — `feedback linkval 불일치` → 1차는 통과했는데, `PAYAPP_LINKVAL` 환경 변수 값이 PayApp이 실제로 보낸 `linkval`과 달랐다.

`linkval`은 PayApp이 피드백 요청마다 자체 생성해 담아 보내는 서명 값이다. 코드에선 `.env`에 저장된 정적 값과 비교했는데, 이게 PayApp의 실제 동작 방식을 잘못 이해한 것이었다. 공식 문서에 이 동작이 명확하게 기술되어 있지 않았고, 개발 모드 테스트로는 실제 피드백 요청이 오지 않아 발견할 수가 없었다.

검증 로직을 올바른 방식으로 교체하고, `app/api/pay/payapp/feedback/route.ts`를 수정했다.

## 같은 세션에서 터진 다른 버그들

크레딧 버그를 잡은 김에 추가 문제가 보였다.

면접이 끝나면 리포트를 받는다. 그런데 리포트를 확인할 UI가 없었다. 면접 페이지에서 세션이 끝나면 그냥 끝났다.

```
이미 진행된 면접에 대해서 면접 리포트 어디서 확인해? 확인할 곳이 없는데?
```

`/reports` 페이지를 새로 만들고(`app/[locale]/reports/page.tsx`), 계정 페이지의 크레딧 사용 내역은 기본 접힘 상태로 바꿨다. `Collapsible.tsx` 컴포넌트를 분리해 붙였다.

성능도 잡았다. 사이트 초기 로딩이 느리다는 걸 확인했더니 첫 페이지 렌더에 DB 쿼리가 직렬로 걸려 있었다. 쿼리 구조를 바꾸고 `vercel.json`에 엣지 캐시 설정을 추가했다. 직접 체감할 수 있을 정도로 빨라졌다.

9시간 49분 세션 — Bash 60번, Read 24번, Edit 22번.

## 그 전날: PayApp을 왜 골랐나

PayApp을 붙인 건 하루 전 세션이었다. 처음엔 카카오페이를 연동했다. KakaoPay REST API `ready`/`approve` 엔드포인트를 구현하고 `KakaoBuy.tsx` 컴포넌트까지 만들었다. 그런데 실결제를 하려면 가맹점 심사가 필요했다. 사업자등록은 있었지만 심사 기간을 기다릴 수 없었다.

대안을 조사했다. 수수료 비교:

| 서비스 | 영세 기준 | 심사 | 특징 |
|---|---|---|---|
| 페이앱 | 1.9% | 없음 | 링크 결제 즉시 가능 |
| 토스페이먼츠 | 0.5~1.5% | 필요 | 가장 저렴하지만 심사 있음 |
| 카카오페이 | 1.5% | 필요 | 가맹 심사 대기 |

즉시 연동이 가능한 건 PayApp 하나였다. 수수료는 비싸지만 시간 비용을 생각하면 선택지가 없었다. `PayAppBuy.tsx` 컴포넌트와 `lib/payments/payapp.ts`를 그날 다 만들었다.

문제는 실결제 전엔 웹훅 피드백을 받을 수가 없어서, `linkval` 검증 로직의 오류가 다음 날까지 숨어 있었다는 것이다.

## 결제 모듈은 실결제로만 검증된다

외부 PG 연동에서 가장 위험한 건 개발 모드 테스트로 검증할 수 없는 부분이다. PayApp의 `linkval`처럼 피드백 요청에만 담겨 오는 값은 실제 결제가 일어나기 전까지 볼 수가 없다.

해결 순서는 결국 단순했다: 빠르게 프로덕션에 올리고, 직접 실결제하고, 런타임 로그를 본다. Vercel 런타임 로그가 없었다면 `linkval 불일치` 에러를 재현하는 데 훨씬 오래 걸렸을 것이다.

이번 세션에서 진단 스크립트(`scripts/diag-payapp.mjs`)도 따로 만들어 뒀다. 다음 결제 이슈가 생기면 로컬에서 PayApp 피드백 필드를 시뮬레이션해 검증할 수 있다.
