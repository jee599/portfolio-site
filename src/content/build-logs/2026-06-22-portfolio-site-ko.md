2일, 세션 10개, tool calls 633회. 치과 광고 대행, AI 면접 플랫폼, 사주앱 X 봇, 정부지원사업 신청, 게임 추천 보고서까지 — 도메인이 완전히 다른 작업들이 하나의 세션 스트림으로 흘렀다.

## 42개 지원사업을 에이전트로 살아있는지 확인했다

세션 9에서 가장 규모가 컸다. "preterview와 치과 광고 대행 두 사업에 핏한 정부·민간 지원사업을 모두 찾고, 통과 확률까지 내서 지원 형식에 맞게 내용을 채워달라"는 요청이었다.

`~/funding/`에 이미 6월 17일에 조사한 프로그램 30건, 6월 21일 사업계획서 워크플로 결과물이 있었다. 새로 조사하는 게 아니라 **기존 리서치를 기반으로 live-verify하고 실제 신청 폼을 채우는** 작업이었다.

워크플로 구성은 두 단계였다. 첫 번째는 검증 — 6개 에이전트가 각 프로그램 카테고리(AC 지분, 정부 무지분, 도시형 가속, 기술사업화, 글로벌)를 병렬로 받아 현재 모집 중인지, 마감일이 맞는지, 1인 지원 가능한지를 실시간 웹 접근으로 확인했다. 두 번째는 필 — 검증 통과한 프로그램에 대해 12개 에이전트가 각각 신청 콘텐츠를 작성했다.

최종 42개 프로그램이 검증됐고, 12개 사업계획서·지원서 초안이 `~/funding/apply-2026-06-22/applications/`에 생성됐다. 파일 예시: `01-프라이머29기-preterview.md`, `13-K-Global-멘티사업계획서.md`, `15-1인창조기업센터-사업계획서.md`.

중요한 건 **통과확률을 두 번 추정했다**는 것이다. 세션 10에서 13개 프로그램×사업 유닛을 "독립 추정 → 회의적 재보정" 파이프라인으로 다시 돌렸다. 에이전트 단일 추정은 낙관 편향이 생기기 때문에, 별도 에이전트가 비판적으로 보정한다. 프라이머 29기(preterview) 23%, 링크업 치과 31% 등 차가운 숫자로 정리됐다.

## Google Play 스크린샷 자동 추출로 게임 카탈로그 만든 방법

세션 8은 "친구 4~6명이 같이 할 수 있는 모바일 게임 추천 보고서"였다. 스크린샷이 핵심인 카탈로그 보고서라 기존 텍스트 렌더러(`md2report/report.py`)를 쓸 수 없었다. OD 동급 디자인의 카탈로그형 HTML을 직접 만들어야 했다.

먼저 후보 게임 8개를 정하고(AFK Journey, 세븐나이츠 키우기, 에버소울, 버섯커 키우기, 레전드 오브 슬라임, 블루 아카이브, 화이트아웃 서바이벌, 라스트 워), 리서치 워크플로를 백그라운드로 띄웠다. 그 동안 스크린샷 추출 방식이 실제로 되는지 검증했다.

```bash
# Google Play CDN에서 직접 추출 — appId만 있으면 작동
curl "https://play-lh.googleusercontent.com/appId..." -o screenshot.png
```

`=w` 앞 베이스 URL로 원하는 해상도를 뽑을 수 있었다. 각 게임 7~14장, 총 8개 게임 아이콘 + 실제 인게임 스크린샷을 전부 수집했다. 프로모 배너가 아닌 실제 인게임 화면인지 확인하기 위해 로컬 HTTP 서버로 컨택트 시트를 띄우고 `mcp__claude-in-chrome`으로 직접 눈으로 확인했다.

외부 API 없이 Google Play CDN URL 패턴만으로 고해상도 스크린샷을 자동 수집하는 패턴 — 앞으로 앱 카탈로그 종류의 보고서에 계속 쓸 수 있다.

## preterview 면접 데모를 GIF로 만든 과정

세션 7에서 "preterview 실제 면접 과정이랑 결과 보고서 받는 거 예시 애니메이션 15~30초짜리 만들어줘"라는 요청이 들어왔다. 바이럴용 소재였다.

방식은 Playwright로 `preterview-demo.html`을 렌더링하고 스크린샷 시퀀스를 찍어 GIF로 합치는 것이었다. 처음엔 `--user-data-dir` 옵션이 문제를 일으켜 실패했다. 옵션을 빼고 재실행해서 통과했다.

피드백이 몇 가지 왔다. "너무 빨라", "유저 답변도 보여야 해", "AI 아이콘이 너무 AI 티가 난다". 매 수정마다 GIF를 재생성하고 확인했다. 최종적으로 답변 텍스트 오버레이 추가, 타이밍 슬로우다운, 스파클 아이콘 제거 세 가지를 적용했다.

바이럴용 스크린샷은 따로 더 찍었다 — 면접 진행 화면, 결과 보고서 화면, 포트폴리오 점검 화면 각각. `preterview-demo.html`, `preterview-portfolio.html`, `preterview-product.html` 세 파일을 각각 목적에 맞게 만들었다.

## 사주앱 X 봇: 6시간 고정 발행을 버렸다

세션 3. 사주앱의 X 봇이 `20 */6 * * *` 로 6시간마다 고정 발행하고 있었다. 자동화 티가 너무 난다는 판단이었다.

수정은 세 가지였다. 첫째, `slotCounter` 방식을 버리고 날마다 다른 4개 타임슬롯으로 불규칙화했다. 둘째, 스레드 포맷(연속 트윗)을 `ACTIVE_FORMATS`에서 제거했다. 셋째, `viral.ts`와 `generate.ts`에서 AI 말투 스크럽을 강화하고 모델을 업그레이드했다.

`vercel.json` cron 표현식은 `*/15 * * * *`으로 바꿨다. 발행 게이트 로직이 `route.ts` 앱 레이어에서 슬롯을 직접 계산해 처리한다. 수정 파일 7개, Bash 25번, Edit 10번, Read 13번.

## dental-clinic 에이전트 위임: 실패 케이스 하나

세션 4(정기 측정)는 tool calls 2개로 끝났다. `Agent(dental-clinic)`에 위임하고 결과 다이제스트만 확인. `동백 임플란트` 블로그 8위 유지, 점수 33 무변경. 깔끔했다.

세션 5(주간 콘텐츠 준비)는 서브에이전트가 `sync.sh` 중간에 죽었다. 콘텐츠는 다 만들어졌는데 커밋이 안 된 상태였다. 에이전트 마지막 메시지가 "course-syntax 오류였습니다. sync.sh를 실행합니다."로 잘려 나왔다. 신뢰하지 않고 파일시스템을 직접 확인했다.

```bash
git status  # uncommitted 확인
# 의료법 컴플라이언스 린터 수동 실행
# HTML 구조 검증
git commit  # 직접 마무리
```

린터 결과: 101문장, 경고 0. 마크다운 기호 없음 확인. 이후 `sync.sh` 수동 실행, 커밋 `91a6704`, 12파일 +429, 푸시·Vercel 재배포 완료. 에이전트 결과는 항상 검증한다.

## 네이버 의료광고 심의: 브라우저로 이력 찾기

세션 6에서 네이버가 파워링크 소재를 막았다. "심의필번호 미기재." `mcp__claude-in-chrome`으로 `dentalad.or.kr`을 직접 탐색했다. computer 21번, navigate 5번, javascript 10번.

SSL 오류가 먼저 났다. 정확한 경로를 다시 확인하고 `dentalad.or.kr/main/`으로 들어가서 로그인 구조와 마이페이지 위치를 파악했다. 2023년에 발급된 심의필번호 `P_2023032120119`(조건부승인)가 이미 있다는 걸 이력 화면에서 확인했다. 로그인 자격증명은 없어서 그 이상은 진행 못 했고, 확인된 사실만 보고했다.

브라우저 자동화가 유용한 케이스 — 외부 행정 시스템 탐색처럼 API가 없고 화면만 있는 곳이다.
