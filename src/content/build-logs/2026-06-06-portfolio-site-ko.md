하루에 Claude Code 세션을 48개 돌리면 뭐가 생기나. 2026-06-05 기준 총 695 tool calls, 프로젝트 4개, HTML 보고서 8개, PayPal API 모듈 10개, saju_global 코드 38개 파일 수정. 그리고 설계 게이트가 다른 세션한테 뺏기는 버그 하나.

**TL;DR** Codex가 읽기 전용 리뷰어로 Claude 작업물을 검증하는 워크플로가 실제로 작동한다. ultraplan은 10개 병렬 에이전트로 785K 토큰을 쓰고 4시간짜리 세션을 만들었다.

## Codex가 잡은 PayPal 25자 제한

PayPal Invoicing v2 API는 `invoice_number` 필드를 최대 25자로 제한한다. 세션 4에서 PayPal 연동을 구현했을 때는 dry-run 경로만 테스트했다. dry-run에서 생성되는 번호는 `JDLAB-MADEINN-VT-20260605` — 정확히 25자.

문제는 라이브 경로였다. 타임스탬프(`HHMMSS`) 접미사를 붙이면 `JDLAB-MADEINN-VT-20260605-114827` — 32자. 세션 5는 이 버그를 Codex가 읽기 전용 리뷰에서 발견한 뒤 Claude에게 픽스 브리프로 전달하는 식으로 시작됐다.

픽스 구조는 간단했다. prefix를 압축하고 타임스탬프를 epoch ms로 base36 인코딩해 7자 안에 넣는다.

```js
// 이전: JDLAB-MADEINN-VT-20260605-114827 (32자)
// 이후: JL-VT-20260605-3K7Z2A (22자)
```

테스트도 같이 업데이트했다 — 배치 전체가 25자 이내임을 검증하는 assertion을 추가했다. Edit 6회, Read 5회, Bash 5회. 세션 시간 4분.

Codex-Claude 분업 패턴이 여기서 잘 드러난다. Claude는 구현에 집중하고, Codex는 읽기 전용으로 엣지 케이스를 찾는다. 같은 컨텍스트 안에서 두 역할을 동시에 하면 보통 구현 쪽에서 시각이 좁아진다.

## 설계 게이트가 다른 세션한테 뺏긴 사례

`hooks/design-gate.sh`는 `.html/.htm` 파일 쓰기를 차단하고, `hooks/design-pass.sh`로 Open Design 등가 패스를 확인한 뒤에만 해제한다. 세션마다 `design-gate.ok`에 세션 ID를 기록하는 방식이다.

세션 6에서 펀넬 보고서 HTML을 쓰려고 게이트를 확인했더니 차단됐다. 이미 ack를 했는데도. 로그를 보니 동시에 돌던 `jidonglab-site` 세션(`a45e846e`)이 게이트 상태를 가져가 자신의 세션 ID로 덮어쓴 것이다.

해결 방법은 단순했다 — 재확인 후 재시도. 하지만 이 버그가 흥미로운 건 원인 자체다. 설계 게이트는 단일 파일로 공유 상태를 관리한다. 두 세션이 동시에 돌면 race condition이 생긴다. 세션을 병렬로 많이 돌수록 이 충돌 확률이 올라간다.

실용적 해결책으로는 세션 ID를 체크하지 않고 게이트 상태를 파일이 아닌 세션별 임시 경로에 저장하는 방식이 있다. 당장 고친 건 아니고 기록만 남겼다.

## ultraplan: 10개 에이전트, 785K 토큰, 4시간

세션 14는 `/ultraplan` 명령으로 시작됐다. `saju_global` — Next.js 모노레포, Vercel 배포, 글로벌 판매 준비 상태 전수 감사를 요청하는 브리프였다.

로컬 git 레포가 없어서 remote 세션 실패로 시작했다. 그래서 로컬에서 직접 Workflow를 구동했다.

워크플로 구성:
- **Phase 1 (병렬)**: 결제 로직, 엔진/사주 계산, i18n/법적 요건, 퍼널/UX를 각 에이전트가 코드베이스 직접 탐색
- **Phase 2 (병렬)**: 글로벌 시장, 일본, 동남아, 인도/중화권, 서구권 채널 경제학을 5개 에이전트가 소스 인용 리서치
- **Phase 3**: 30일 매출 극대화 플랜 합성

결과: 10개 에이전트, ~785K 토큰, 161K chars 출력. 세션 시간 3시간 49분, tool calls 195회.

실질적으로 발견된 문제들:
- PayPal webhook signature 검증 누락
- 한국 결제(Toss) 제거 후 글로벌 전용 전환 필요
- GDPR/DPDPA 쿠키 동의 컴포넌트 없음
- 일본 특定商取引法 고지 페이지 미완성

이 세션 하나에서 38개 파일 수정, 19개 파일 신규 생성이 나왔다. Bash 79회, Read 49회, Edit 46회, Write 18회.

ultraplan 옵트인이 없었다면 이 규모의 팬아웃은 일어나지 않았을 것이다. `ultraplan` 키워드 하나가 워크플로 실행 허가를 명시적으로 부여한다. 비용은 크지만, 전수 감사를 혼자 읽어가며 하는 것보다 빠르다.

## PayPal 이미지 4번 반복한 이유

세션 10~13은 PayPal 결제 링크에 올릴 상품 이미지를 만드는 작업이었다. 한 번에 완성되지 않고 4회 반복됐다.

- **세션 10**: 초기 이미지. `yourstore.com` 플레이스홀더 사용, 파란 액센트
- **세션 11**: jidonglab.com 실 브랜드 반영. 초록 액센트, Pretendard, 실제 사이트 카피
- **세션 12**: 영문 납품물 상세 내용 추가. 구매자가 받을 내용을 이미지 안에 표시
- **세션 13**: "두꺼운 보고서" 느낌 강화. 섹션, 목차, 데이터 테이블을 밀도 높게

각 세션은 Python 생성기(`build.py`)로 SVG를 만들고 Chrome headless로 PNG 래스터라이즈하는 파이프라인을 그대로 사용했다. 변한 건 이미지 컨텐츠와 레이아웃 밀도였다.

반복이 많았던 이유는 브리프가 한 번에 완성되지 않아서다. "jidonglab 브랜드로" → "영문 납품물 설명 넣어" → "보고서처럼 두껍게 보이게" 순서로 요구사항이 단계별로 추가됐다. 처음부터 이 세 조건이 같이 왔다면 세션 하나로 끝났을 것이다.

브리프를 쓸 때 최종 사용 맥락을 먼저 확인하는 게 중요하다. PayPal 상품 이미지는 썸네일로 축소된다. 96px에서 가격과 제목이 읽혀야 한다는 제약이 처음부터 있었다. 이걸 세션 시작에 브리프에 넣었다면 1~2회 반복으로 끝났을 것이다.

## 세션 간 컨텍스트 전달 패턴

48 세션 중 많은 세션이 이전 세션 결과를 참조하는 방식으로 시작됐다. Hermes(오케스트레이터)가 세션 간 릴레이를 담당하고, Claude Code는 각 세션 안에서 구현만 맡는 분업 구조였다.

이 패턴의 장점은 각 세션이 명확한 목표를 갖는다는 것이다. 단점은 이전 세션의 문맥을 매번 브리프에 요약해서 전달해야 한다는 것이다. 브리프가 충분히 구체적이지 않으면 Claude가 이전 작업과 불일치하는 결정을 내린다.

세션 7~9의 PayPal 가격 정정(세션 7: `$149`→픽스, 세션 9: `$79/$299` 확정)이 이 패턴의 비용을 보여준다. 가격 구조가 한 세션 안에서 결정되지 않고 여러 세션에 걸쳐 정제됐다. 각 세션이 이전 것을 보정하는 식이었다.

고쳐졌나: 세션 9 이후 `src/paypal/leads.js`, `config/paypal-hot-leads.example.json`, `test/paypal.test.js`, `docs/paypal-integration.md`, `docs/jdlab-paid-offers.md` 모두 `$79/$299` 기준으로 정렬됐다. Edit 12회, Bash 9회.
