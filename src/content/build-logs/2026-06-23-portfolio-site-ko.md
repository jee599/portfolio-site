코드잇이 6월 17일에 AI 모의면접 '어센트'를 출시했다. 엿새 후인 지금, Preterview Claude Code 세션 기록을 보면 — 11세션, 664 tool calls, 가장 긴 단일 세션 27시간 28분이다.

**TL;DR** 경쟁사 출시 직후 실사 아바타 면접관(HeyGen + Simli), Paddle 해외결제, 24-에이전트 광고 전략 리서치, 콜드메일까지 동시에 밀어붙인 기록이다. 가장 큰 병목은 코드가 아니라 비용 제약이었다.

## 코드잇이 먼저 냈다

세션 10에서 "코드잇에서 낸 내 프리터뷰랑 비슷한 기능이 있는 것 같은데 지금 기준 비교해줘"라는 요청이 들어왔다.

Claude가 먼저 한 건 제품 파악이었다. Preterview 쪽(이력서 빌더 + 포트폴리오 5차원 점검 + AI 면접관 3인 음성 모의면접, 크레딧 과금, 글로벌 타깃)을 스캔하고, 코드잇 쪽을 확인했다. 결과: **어센트(Ascent), 2026년 6월 17일 출시**. 딱 엿새 전이었다.

워크플로우가 두 단계로 돌아갔다. 첫 번째 워크플로우는 코드잇 어센트의 실제 기능과 Preterview와의 겹치는 지점을 조사했다. 두 번째는 "우리가 더 낫게 하고 잘 팔리려면 어떻게 해야 돼"에 답하는 실행계획 — 경쟁사 해부, 내부 갭 감사, 채널·가격 조사, 초안, 자가비판, 실행계획 순서였다.

나온 결론은 명확했다. 겹치는 부분은 "면접 후 리포트(태도·전달력 + 역량 다차원 채점)"와 "이력서/자소서→예상질문·꼬리질문"이었다. 정면 충돌이 아니라 인접 시장이지만, 타이밍이 있었다.

## 335 tool calls — 비주얼 면접 세션

세션 5는 이 한 문장으로 시작했다.

> "실제 zoom 면접처럼 면접관 3명의 얼굴을 3D 랜더링으로 그리고, 입모양 싱크맞추고 내 화면까지 요구하고, 마이크쓰게하는 면접이야"

27시간 28분, 335 tool calls. 이 세션 하나가 전체 11세션 tool calls의 51%다.

Claude가 먼저 한 건 스코프 분리였다. 두 갈래로 나눴다.

**스코프 A** — 푸시투토크. 내가 말하고 제출하면 면접관이 응답. 화면은 Zoom이지만 턴제다.

**스코프 B** — 진짜 실시간. 계속 듣고 있다가 끼어드는 방식. WebRTC + VAD가 필요하고 비용/공수의 90%가 여기 있다.

스코프 A로 확정하고 나서 벤더 선택으로 들어갔다. 3D 모델이 먼저 들어갔다. 그랬더니 바로 "실사 아바타는 어떻게 전환해?"가 나왔다.

Claude가 웹 서치로 HeyGen Streaming API, Simli, LiveAvatar, D-ID를 실측 검증했다. 그 중 Preterview 아키텍처(턴 기반이라 사전 생성 가능)에 맞는 조합이 확정됐다 — **HeyGen으로 아바타 스트리밍, Simli로 실시간 립싱크**.

생성된 파일 수: 8개 신규 생성, 6개 수정. `HeyGenAvatarTile.tsx`, `SimliAvatarTile.tsx`, `VisualInterviewPoc.tsx`, `heygen.ts`, `simli.ts`, API 라우트 3개.

`mcp__claude-in-chrome__computer` 호출이 48번이다. 브라우저를 직접 제어하면서 UI 상태를 눈으로 확인하고 수정했다. 세션 중간에 실제 대화 흔적이 그대로 남아있다.

```
"아직도 3d모델이 나와"
"안돼"
"서버 재시작 너가 해주면 되잖아"
```

`.env.local`이 없어서 API 키 연동이 안 됐고, 서버 재시작 없이 변경이 반영 안 됐다. 3개 아바타를 동시에 띄우려 했는데 1개만 됐던 문제도 있었다 — Simli 동시 세션 제한이었다.

## "면접 한 번에 1달러 이하로 해야 돼"

비용이 병목이었다. 세션 중간에 이 기준이 나왔다.

> "지금 너무 비싸 말도 안돼 면접 한 번에 1달러 정도 해야돼 20분에 그 이하"

LiveAvatar를 먼저 시도했다. 크레딧을 충전하고 실제 API 키(`xvvpwhwdzwn42of1givn`)를 연동하고 테스트했다. 요금이 기준을 넘었다.

Claude가 워크플로우를 돌렸다 — 24 에이전트가 벤더별 요금을 검증하고 "$1/20분 3면접관" 예산에서 실현 가능한 경로를 좁혔다. 결론은 Simli Free tier 활용 + 아바타를 한 번만 생성해서 재사용하는 방식이었다.

Simli 티어 질문도 나왔다: "simli 어떤 티어로 올려야 돼? pro면 훨씬 더 성능도 좋아져?" — 현재 `artalk` 아바타로 진행하기로 했다.

## Paddle 결제: 기존 구조 읽기가 절반이었다

세션 8 — "paddle 결제 perterview에 붙일거야" 한 마디로 시작했다. 93 tool calls, 15시간 27분.

Claude가 먼저 한 일은 현재 결제 구조 전체를 파악하는 것이었다. `feat/geo-payment-routing` 브랜치가 이미 머지돼 있었다. 한국 → PayApp(₩), 해외 → PayPal($) 구조가 갖춰진 상태였고, 크레딧 팩 3종(9,900 / 49,000 / 99,000원), 멱등 적립 로직, 웹훅 기반 fulfillment 패턴까지 다 있었다.

결론은 단순했다: **해외 경로(PayPal)만 Paddle로 교체**. 한국 PayApp은 건드리지 않는다.

구현 전에 Paddle 공식 문서를 실측 검증했다. 웹훅 서명 검증을 틀리면 치명적이기 때문이었다. 4개 영역(클라이언트 체크아웃, 웹훅 서명, 주문 생성, 크레딧 적립)을 별도로 확인하고 나서 코드를 썼다.

생성된 파일: `lib/payments/paddle.ts`, 세 개의 API 라우트(create/webhook/confirm), `PaddleBuy.tsx`, `docs/paddle-setup.md`. 도구 사용: `Bash(40)`, `Read(18)`, `Edit(10)`, `Write(6)`. 비주얼 면접 세션보다 Read 비율이 높다 — 기존 패턴을 정확히 따르는 데 시간을 더 썼다는 뜻이다.

Paddle 샌드박스 API 키(`pdl_sdbx_apikey_...`)도 세션 중에 직접 넣었다. 셋업 가이드는 `docs/paddle-setup.md`에 남겼다.

## Ultracode 광고 전략: 에이전트 24개, 880k tokens

세션 9 — `/effort ultracode`로 시작해서 워크플로우를 두 번 돌렸다.

첫 번째: "인스타가 나아? 얼마를 어떤 타겟에 태우는게 가장 효과적인지 객관적인 수치랑 근거로 서칭해줘. 국내 / 글로벌 모두"

5개 에이전트가 병렬로 돌아가면서 2024~2025 실측 벤치마크를 수집했다 — 네이버 파워링크 CPC, 메타 코리아 CPM, 카카오모먼트, 글로벌 메타·틱톡, Reddit. 결과를 적대적 검증으로 돌렸더니 13개 핵심 수치 중 13개가 수정됐다. 에이전트 단일 추정은 낙관 편향이 있기 때문이다.

두 번째 워크플로우: "해줘 1, 2, 3" — 네이버 파워링크 셋업, Reddit 광고 소재 3개, 픽셀+랜딩 체크리스트를 각각 플랫폼 제약에 맞게 QA 검증하면서 만들었다.

총 24 에이전트, 약 880k tokens. tool calls 수는 18개지만 워크플로우 내부 에이전트 호출 수는 그 배수다.

## 데모 영상 + 세일즈 페이지 + 콜드메일

세션 4에서 `preterview-demo.html`을 게임 개발자 포트폴리오 기반 면접으로 재작성하고 영상으로 뽑았다. Playwright로 `?capture=1&t=<seconds>` 파라미터를 이용해 프레임을 추출하고 ffmpeg로 인코딩했다. `preterview-demo-ko.mp4`와 `preterview-demo-en.mp4`, 각 1280×720·30fps·39.5초.

세션 7은 open-design 스킬을 타고 세일즈 페이지와 콜드메일을 만들었다. Preterview의 `globals.css`에서 브랜드 토큰을 직접 추출해서 바인딩했다 — violet 액센트 `#6E56F7`, near-black 히어로. 콜드메일은 인플루언서용과 대학취업지원센터용 두 가지, 이메일 클라이언트 호환 인라인 CSS로 작성했다.

세션 6에서는 5~7턴 공개 데모 페이지를 만들었다. IP 기반 레이트 리밋을 걸어서 Opus API 비용을 제한했다. 비용 계산: 단일 턴(Opus 4.8 입력 $5/1M, 출력 $25/1M)을 실제로 태워서 확인했다.

세션 5(비주얼 면접)와 세션 8(Paddle)이 tool calls의 65%를 차지한다. 두 세션의 공통점은 기존 코드베이스를 먼저 깊게 읽었다는 것이다 — 탐색이 많으면 Bash와 Read 호출이 쌓인다.

세션 2는 1 tool call이다. `Agent(dental-clinic)`에 위임하고 다이제스트만 확인했다. 에이전트 위임은 메인 세션 tool calls에 잡히지 않는다.

남은 것: Simli 립싱크 품질 개선(시선 처리가 아직 어색하다), Paddle 샌드박스 왕복 테스트, Preterview 실행계획 v2의 "8주 안에 첫 결제 N건" 검증.
