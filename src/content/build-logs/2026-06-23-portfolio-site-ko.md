이틀 동안 13개 세션, 총 약 700 tool call로 5개 프로젝트를 동시에 굴렸다. preterview UI 버그픽스, 치과 콘텐츠 준비, X봇 튜닝, 사주앱 배포, 지원사업 확률 보정까지. 같은 Claude Code 세션 하나에서.

**TL;DR** 이걸 가능하게 한 건 멀티에이전트 위임 구조다. 도메인별 전담 에이전트에게 컨텍스트째로 위임하고, 메인 세션은 의도 파악·결과 검증·승인 게이트만 담당한다.

## 도메인 전담 에이전트 위임 — dental-clinic 패턴

`dental-clinic` 서브에이전트에게 치과 작업을 통째로 위임하는 구조가 핵심이었다. 세션 4(정기 측정)와 세션 5(주간 콘텐츠)에서 실제로 돌렸다.

```
메인 세션: "동백유디 정기 측정 — dental-clinic에 위임"
→ Agent tool (subagent_type: dental-clinic)
   └─ ~/dental-promo/dongbaek-uddental/clinic.json 로드
   └─ blog_probe.py로 키워드 순위 실측
   └─ history.json 스냅샷 갱신
   └─ sync.sh → 커밋 + Vercel 재배포
메인 세션: 결과 다이제스트 확인 (Bash 1회)
```

세션 4는 tool call이 단 2개(Agent + Bash)다. 에이전트가 `clinic.json`·`cache`·`history`를 읽어 컨텍스트를 즉시 복원하고, 측정·기록·커밋·배포까지 혼자 처리한다. 메인 세션의 컨텍스트 윈도를 치과 운영 데이터로 오염시키지 않는 게 목적이다.

세션 5(주간 콘텐츠)에서 에이전트가 `sync.sh` 도중에 죽었다. 가비지 출력과 함께 커밋 없이 종료. 이때 메인 세션이 개입했다 — 에이전트의 요약을 믿지 않고, 직접 파일시스템과 git 상태를 확인했다.

```bash
git log --oneline -3   # 커밋 없음 확인
```

에이전트가 "완료"라고 했어도, 커밋이 없으면 완료가 아니다. 독립 검증을 거쳐서야 진짜 상태를 파악했고, 의료법 컴플라이언스 린터도 직접 돌렸다. 에이전트 결과를 trust but verify한다는 게 실제로 이런 뜻이다.

## 12개 에이전트 팬아웃 — 사업계획서 워크플로

세션 7은 127만 토큰짜리 워크플로를 띄웠다. 치과 마케팅 자동화 + preterview 두 사업의 사업계획서를 한 번에 생성하는 작업이었다.

팬아웃 구조:

```
Foundation (병렬 6)
├─ 치과·preterview 제품 프로파일
├─ 정부·공공 비지분 프로그램 리서치
├─ 민간 VC·AC 프로그램 리서치
├─ 정부 PSST 합격사례 설계도
└─ 민간 IR 합격공식

Plans (병렬 2, high effort)
├─ 치과 마케팅 자동화 사업계획서
└─ preterview 사업계획서

Synthesis → Strat → Review
```

왜 이 구조가 필요했냐 — 두 사업의 도메인 지식(치과 의료법, AI 면접, 정부 프로그램 심사 기준)이 서로 독립적이라 같은 컨텍스트에 놓으면 서로 간섭한다. 에이전트별로 격리된 컨텍스트에서 깊게 파고들게 한 뒤, 마지막에 통합했다.

결과물은 7,747단어 분량의 보고서 (`~/funding/bizplan-2026-06-21/REPORT.md`). 단일 세션으로 만드는 건 물리적으로 불가능한 분량이다.

## 13개 프로그램 × 적대적 확률 보정

세션 9에서 지원 프로그램별 통과확률을 냉정하게 뽑는 작업을 했다. 단순 추정 대신 **추정 → 적대적 재보정** 파이프라인을 썼다.

```
프로그램 유닛 13개 (preterview × 7, 치과 × 6)
   ↓ 각각 독립 추정
   ↓ 회의적 검증 에이전트로 교차 보정
   ↓ 냉정한 %값으로 정렬
```

단일 추정이면 내 편향이 들어간다. 별도 에이전트가 같은 근거를 놓고 "왜 이 확률이 너무 높냐"를 따지면, 첫 추정이 낙관 편향으로 부풀려졌을 때 잡힌다. 프라이머 29기는 1차 추정 25% → 재보정 12%로 내려갔다.

## preterview i18n 버그 — 193 tool call짜리 삽질

세션 2가 제일 tool call이 많았다. 193개. 모의면접 화면에서 버튼 텍스트가 `interview.room.endInterview`로 raw 키가 노출되는 버그였다.

초기 가설: 키 파일에 없다 → 확인해보니 en/ko 양쪽에 존재함.  
두 번째 가설: 코드가 잘못된 키를 호출 → `tr("room.endInterview")`로 올바르게 호출하고 있음.

범인은 `scopeClientMessages`였다.

```typescript
// i18n/request.ts
function scopeClientMessages(messages, strippedPath) {
  // strippedPath가 /interview로 시작해야 interview 네임스페이스 포함
  // x-cc-pathname 헤더가 비면 strippedPath = "/" → 네임스페이스 전부 제외
}
```

proxy.ts가 `x-cc-pathname` 헤더를 주입하는데, 이 헤더가 next-intl 미들웨어를 통해 RSC까지 전파된다는 가정이 깨진 곳에서 버그가 터졌다. 클라이언트가 메시지를 못 받으니 raw 키를 그대로 출력하는 거였다.

키 자체를 보는 것만으로는 못 잡는 버그다. 메시지 전달 경로 전체를 봐야 보인다.

## X봇 튜닝 — "gownj" 한 글자로 명령

세션 3에서 사주앱 X봇을 튜닝했다. `gownj`는 한영 전환을 안 하고 친 `해줘`다. 원하는 게 세 가지(발행시간 불규칙화, 스레드 포맷 OFF, AI 말투 제거)였는데 어떤 걸 원하는지를 한 번만 물어보고 바로 진행했다. tool call이 49개 중 Bash 25개, Edit 10개.

발행 스케줄 변경:
```
before: cron "20 */6 * * *"  (매 6h 고정)
after:  cron "*/15 * * * *"  (매일 바뀌는 4개 슬롯, 불규칙)
```

크론 자체는 15분마다 돌지만, 내부 로직에서 당일 예정 슬롯인지 체크해서 하루 4개만 발행한다.

## 의료광고 심의 신청 — 브라우저 자동화

세션 6은 치과 네이버 광고 소재가 "심의필번호 미기재"로 노출 제한된 건이었다. `mcp__claude-in-chrome` 도구로 대한치과의사협회 심의 신청 폼을 직접 조작했다. tool call 중 browser 관련이 36개(computer 21 + navigate 5 + javascript_tool 10).

폼 채우기 중간에 의사면허번호, 개설자 생년월일 같은 민감 정보가 필요해서 멈추고 사용자에게 확인을 받는 구조로 진행했다. 브라우저 자동화가 있어도 승인 게이트는 사람이 쥔다.

## 어떤 작업에 팬아웃을 쓰나

이틀 치 세션을 보면 팬아웃 워크플로를 쓴 경우와 안 쓴 경우의 패턴이 명확하다.

팬아웃을 쓴 경우: 독립적인 리서치 유닛이 10개 이상이고, 각 유닛의 결과가 나머지에게 영향을 미치지 않는 경우. 사업계획서(12개), 지원사업 확률(13개), 게임 추천(8개 × 리서치+검증).

직접 실행한 경우: 하나의 도메인 컨텍스트 안에서 단계가 순차적으로 이어지는 경우. 치과 콘텐츠 준비, preterview 버그픽스, X봇 튜닝.

팬아웃 비용은 토큰이다. 세션 7은 127만 토큰 소진. 그 대신 단일 세션으로는 며칠 걸릴 리서치를 34분에 끝냈다. 트레이드오프를 의식적으로 선택해야 한다.
